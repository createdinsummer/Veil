# Veil CLI

`veil` 是 Veil 的命令行入口。它处理命令解析和用户交互，通过 `VeilService::execute` 调用容器操作；创建、解包和链接路径的业务校验由服务层完成。

## 文档边界

本文负责命令行为、参数、工作流和用户可见限制。密钥封装、磁盘格式、索引结构和恢复算法由 [Core 文档](../veil-core/README.md) 维护。遇到命令输出与内部格式需要分别理解时，应先在这里确认操作路径，再在 Core 文档确认存储语义。

## 安装与构建

开发构建使用 `cargo build --package veil-cli`，发布构建使用 `cargo build --release --package veil-cli`。构建产物为 `target/debug/veil` 或 `target/release/veil`。

也可以通过 `cargo install --path crates/veil-cli` 安装到 Cargo 的用户二进制目录。

## Work / Veil 模型

CLI 当前以 Work 组织 Veil。`veil init` 会创建：

| 对象 | 说明 |
| --- | --- |
| `.veil-link` | 指向 `veil_dir` 的便携入口 |
| Veil 目录 `veil_dir` | 保存 `.veil-info` 和独立 `.enc` 文件 |
| 全局配置记录 | 在本机配置或移动盘配置中登记工作区，并缓存容器信息和链接正文 |

默认 `work_root` 是 `~/.veil/works/default`，每个 Veil 在其中使用以 `veil_id` 命名的 `veil_dir`。链接默认写入当前目录，也可以通过 `--link` 指定。

Veil 名称允许重复，但 `veil_id` 不允许冲突。创建或解包时如果目标 ID 已经注册，命令会报错，不会覆盖已有记录。同一 Veil 可以生成多个 `.veil-link`。

命令参数既可以使用位置形式，也可以使用选项形式。普通 Veil 命令只接受显式 `.veil-link` 路径、唯一 Veil 名称或唯一 `veil_id`。`veil_dir` 只允许由 `veil link` 用于恢复链接，不能直接传给 `add`、`list`、`shell` 等命令。

所有需要选择已有 Veil 的命令都必须经过统一的 `commands::resolve_veil`。该函数最终会读取 `.veil-info`，返回确认后的 `veil_id` 和 `veil_dir`；后续 `VeilManager` 绑定这个 ID，并在每次元数据访问时校验实际身份。`veil link` 使用单独入口，额外允许输入 `veil_dir`。

## 详细命令

### 初始化

`veil init <veil-name>` 创建 Veil、`veil_dir`、配置记录和链接。密码可以交互输入，也可以通过位置参数、`--password` 或 `VEIL_PASSWORD` 提供。

初始化还支持以下选项：

| 选项 | 作用 |
| --- | --- |
| `--link <路径>` | 指定链接输出位置 |
| `--work <名称>` | 使用已注册的命名 Work，参数是名称而不是路径 |
| `--work-root <路径>` | 指定工作区根路径，自动登记工作区并关联当前 Veil |
| `--dedicated` | 让指定工作区只保存当前 Veil，目录仍为 `work_root/veil_id` |
| `--portable` | 使用链接所在盘的固定配置和默认工作区，不能与 Work 选项同时使用 |

本机创建默认使用 `~/.veil/config.jsonc` 中的默认工作区；链接目标位于移动盘时，默认使用 `<盘根目录>/.veil/config.jsonc` 中的默认工作区。`--portable` 按链接所在盘选择上述固定配置位置。本机默认目录为 `~/.veil/works/default`，移动盘默认目录为 `<盘根目录>/.veil/works/default`，配置中的 `path` 均为 `works/default`。

`--work` 选择已登记工作区名称，`--work-root` 指定目录并自动登记到该目录所属盘的配置。配置中的相对路径始终基于所属 `config.jsonc` 所在目录解析，不受命令执行目录影响。工作区配置仅保存路径、类型、说明和创建时间。

工作区仅存放以 `veil_id` 命名的容器目录，没有工作区身份文件。默认工作区和自定义工作区允许多个容器，专属工作区只允许一个容器。容器整体剪切到已登记的其他工作区或移动盘后，原链接和原 ID 继续有效；需要一起移动 `.veil-info` 和全部 `.enc` 文件，不需要重新加密。

### 添加文件

`veil add <veil> <源文件或目录>` 读取本地内容，加密后写入 `veil_dir`，并更新 `.veil-info`。

单文件可以使用位置目标路径或 `-o` 修改 Veil 内名称。目录会递归导入，并保留相对目录结构；未指定目标时使用源目录名作为 Veil 内前缀。同名目标采用替换语义，不会累积重复条目。错误密码会在写入任何密文前失败。

### 列出和查看

`veil list <veil>` 输出文件名称、大小、加密时间和总大小。

`veil free <veil>` 按原始相对路径构造真实父子目录树，并使用 `├──`、`└──`、`│` 绘制标准树状结构。文件和目录按名称排序，目录名带 `/`。

`veil info <veil>` 输出 Veil 名称、稳定 ID、`veil_dir`、Work 类型、创建时间、文件数量、内容总大小、实际目录占用、MIME 类型分布和按虚拟路径排序的文件清单。

`veil exists <veil> <路径>` 判断 Veil 内文件或隐式目录是否存在。文件或目录存在时退出码为 `0`，不存在时输出 `不存在` 并返回退出码 `1`，适合直接用于脚本判断：

```bash
if veil exists photos.veil-link vacation/photo.jpg -p 'password'; then
  echo "file exists"
fi
```

### 导出文件

`veil ex <veil> <Veil 内路径> <输出路径>` 解密指定文件并写入本地路径。输出路径是必填项。

当前 CLI 按精确虚拟路径查找单个文件。虽然帮助文本保留了通配符描述，但当前命令层调用的是单文件导出接口。

### 删除和重命名

`veil rm <veil> <Veil 内路径>` 删除文件，或递归删除目录内的全部文件。路径会进行 Veil 内规范化，支持 `./tree` 这类写法；Veil 根目录和 `..` 路径逃逸会被拒绝。删除时会先提交更新后的元数据，再清理失去引用的密文。

`veil mv <veil> <原路径> <新路径>` 修改 `.veil-info` 中的原始路径。文件可以重命名或移动到已有目录；目录移动时会同步更新全部子文件路径前缀。该操作不会移动或重命名磁盘上的随机加密文件名，也不会重新加密文件内容。

目标已经存在时拒绝覆盖；目录不能移动到自身或子目录。源路径和目标路径都会进行 Veil 内规范化，支持 `./tree` 这类写法。

### 修改密码

`veil passwd <veil>` 默认只修改密码保护层。Veil 使用随机数据主密钥分块加密文件，密码派生密钥只保护元数据；默认改密重新生成 salt 和密码派生密钥，并重新加密元数据，不修改任何 `.enc` 文件。

使用 `veil passwd --full <veil>` 时，程序会生成新的数据主密钥，并逐个流式重写全部文件。文件按固定大小分块读取、解密、重新加密和写入，不会把整个文件一次性加载到内存。迁移期间元数据同时保存新旧数据主密钥：每个文件更新后立即提交元数据，读取时先尝试当前数据主密钥，失败后再尝试旧密钥。这样中断只会留下可读取的旧文件或新文件，不需要为整个 Veil 预留第二份空间。旧密码会一直有效，直到全部文件迁移完成并提交最终元数据；中断后用旧密码再次执行完整改密即可继续。

位置参数形式为旧密码、新密码；选项形式使用 `--password` 和 `--new-password`。`--full` 也可以写作 `--reencrypt`。

### 交互式 shell

`veil shell <veil>` 验证密码后进入交互循环。当前支持：

| 会话命令 | 作用 |
| --- | --- |
| `ls` 或 `list` | 列出文件 |
| `info` | 显示 Veil 信息 |
| `add <文件>` | 添加文件 |
| `rm <文件>` | 删除文件 |
| `ex <文件> <输出>` | 导出文件 |
| `help` | 显示会话帮助 |
| `exit`、`quit` 或 `q` | 退出 |

Shell 不缓存派生密钥。每次文件操作仍由 `VeilManager` 读取并解密必要的元数据或文件，因此它主要提供操作便利，不应被描述为批量操作的性能缓存。

## 打包与解包

`veil pack <veil>` 把 `veil_dir` 的加密元数据和已有密文写入单个 `.veil` 文件。默认输出名是 `<veil-name>.vault.veil`，可用 `--output` 覆盖。

打包阶段不重新加密文件内容。输出文件已经存在时，命令会拒绝覆盖。

打包先写入同目录临时文件，全部数据和头部校验完成后才原子替换目标路径，中途失败不会留下损坏的 `.veil` 包。

`veil unpack <文件.veil>` 读取包内元数据，分配新的 `veil_dir`，并在密码验证通过后重建 `.veil-info`、Veil 配置和链接。密码错误、包损坏、路径不安全或配置写入失败时，会清理新建目录、链接和半成品文件。

常用选项如下：

| 选项 | 作用 |
| --- | --- |
| `--name <名称>` | 指定解包后的展示名称 |
| `--work <名称>` | 指定命名 Work |
| `--link <路径>` | 指定新链接位置 |
| `--password <密码>` | 提供容器密码 |

## 配置与提示

`veil config` 或 `veil config show` 显示配置文件路径、有效提示级别、默认 Work、自定义 Work 及容器缓存、链接缓存数量。`veil config --hints full|brief|off` 修改提示级别。

提示级别也可以通过 `VEIL_HINTS` 临时覆盖。`full` 显示全部提示，`brief` 只保留关键恢复和解包提示，`off` 关闭提示。

本机配置位于 `~/.veil/config.jsonc`，各移动盘配置位于 `<盘根目录>/.veil/config.jsonc`，主要内容包括：

| 配置项 | 说明 |
| --- | --- |
| Work | 默认工作区和自定义工作区的路径、类型、说明和创建时间 |
| Veil 记录 | `veil_id`、展示名称、容器创建时间和链接列表，仅作为缓存 |
| 链接缓存 | `links[].link` 对象与 `.veil-link` 共用正文结构，仅包含版本、链接创建时间和容器身份，外层保存链接路径、状态和最近观察时间 |
| `user_settings` | 操作提示级别 `hint_level`，取值为 `full`、`brief` 或 `off` |

配置文件和 `.veil-link` 的正文均使用 JSONC，支持 `//` 行注释、`/* ... */` 块注释和尾逗号。修改配置时保留未删除字段的注释；不读取旧的 TOML 文件。CLI 文案资源使用编译时嵌入的 `i18n/messages.jsonc`。

## 链接管理

`veil link <veil-name、ID、链接或 veil_dir>` 生成新的 `.veil-link`。如果已有链接，命令会复制原文件并缓存结构化正文；如果 Veil 已经登记但没有链接，则按配置重新生成；如果只能定位到 `veil_dir`，则从 `.veil-info` 明文头部读取身份。输出会按需创建父目录，必须以 `.veil-link` 结尾；配置缓存失败时会删除刚写出的链接。

多个链接可以指向同一 `veil_dir`，因此通过任一链接执行的写操作都会影响同一份元数据和文件。

配置中存在对应链接记录时，缺失链接可以在后续解析过程中使用 `link` 对象重新生成。重建前校验链接字段，保留完整字段值，不保留原文件的注释和排版。

## 密码输入顺序

命令按以下顺序尝试获取密码：

1. 命令行参数或对应选项。
2. `VEIL_PASSWORD` 环境变量。
3. 当前终端交互输入。

新建容器或修改密码时，交互模式要求输入两次。参数和环境变量方式会跳过二次确认。

`veil passwd` 的旧密码使用 `VEIL_PASSWORD`，新密码使用 `VEIL_NEW_PASSWORD`。未设置新密码环境变量时进入交互输入，避免把旧密码静默复用为新密码。

命令行密码可能进入 shell 历史或进程参数列表。需要自动化的场景优先使用环境变量或受控的调用环境。

## 输出与本地化

CLI 默认输出中文，也可以通过 `VEIL_LANG` 选择语言。当前资源包含中文和英文。

Windows 控制台会根据输出代码页转换提示文字；Unix 平台按 UTF-8 输出。文件内容始终按二进制处理，不参与终端编码转换。

`veil help files` 显示各文件扩展名和容器文件的用途说明；`veil help <命令>` 可直接显示对应子命令帮助。`veil help all` 或 `veil help --all` 会输出顶层帮助以及全部子命令帮助。

### 错误码与退出码

所有错误统一输出为：

```text
❌ 错误 [1002]: 参数冲突: [密码] 不能与 --password <密码> 同时使用
```

错误码范围：

| 范围 | 含义 | 默认退出码 |
| --- | --- | --- |
| `1000-1999` | 命令行参数错误 | `2` |
| `2000-2999` | 密码错误 | `1` |
| `3000-3999` | 文件添加错误 | `1` |
| `4000-4999` | 配置错误 | `1` |
| `5000-5999` | `init` 初始化错误 | `1` |
| `6000-6999` | 链接错误 | `1` |
| `7000-7999` | 导出、打包和解包错误 | `1` |
| `8000-8999` | 帮助命令错误 | `1` |
| `9000-9999` | 底层核心错误和未分类异常 | `1` |

错误码和模板参数由统一的 `CommandError` 保存，最终由 CLI 边界按当前语言渲染。

## 并发与一致性

同一 Veil 中，同一文件支持多读单写，不同文件可并行处理；元数据更新串行提交。所有进程都需通过支持该锁协议的 Veil 版本访问同一容器。目录操作和改密还会使用容器级协调锁。

写操作使用写时复制和原子元数据切换。清理在没有其他活动操作时执行。macOS 会拒绝系统标记为网络卷的容器；云同步目录的锁语义尚未验证。元数据发布后如果同步失败，命令会提示状态不确定，应重新打开容器确认结果。

## 测试

CLI 测试位于 `crates/veil-cli/tests`，覆盖初始化、链接、配置、打包解包、密码修改、文件增删导出和 shell 会话。运行整个工程测试使用 `cargo test --workspace --all-targets`。

## 当前限制

- `ex` 当前只处理单文件。
- `shell` 不提供密钥或 Veil 对象的长期缓存。
- `passwd` 默认只重新保护元数据；`passwd --full` 会重新加密全部 `.enc` 文件。
- 链接按容器 ID 扫描已登记工作区；目标盘未挂载时报未找到，同 ID 的多个副本报告歧义。
- 忘记密码后没有恢复通道。
