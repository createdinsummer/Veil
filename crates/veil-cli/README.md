# Veil CLI

`veil` 是 Veil 的命令行入口。它管理全局配置、解析 `.veil-link`、处理密码输入，并调用 `veil-core` 完成工作区、元数据和文件内容的读写。

## 文档边界

本文负责命令行为、参数、工作流和用户可见限制。密钥封装、磁盘格式、索引结构和恢复算法由 [Core 文档](../veil-core/README.md) 维护。遇到命令输出与内部格式需要分别理解时，应先在这里确认操作路径，再在 Core 文档确认存储语义。

## 安装与构建

开发构建使用 `cargo build --package veil-cli`，发布构建使用 `cargo build --release --package veil-cli`。构建产物为 `target/debug/veil` 或 `target/release/veil`。

也可以通过 `cargo install --path crates/veil-cli` 安装到 Cargo 的用户二进制目录。

## 工作模型

CLI 当前以工作区为默认模型。`veil init` 会创建：

| 对象 | 说明 |
| --- | --- |
| `.veil-link` | 指向工作区的便携入口 |
| 容器工作区 | 保存 `.veil-meta` 和独立加密文件 |
| 全局配置记录 | 在 `~/.veil/config.toml` 中登记容器、卷和链接 |

默认工作区根目录是 `~/.veil/workspaces/default`，每个容器在其中使用以 `veil_id` 命名的目录。链接默认写入当前目录，也可以通过 `--link` 指定。

命令参数既可以使用位置形式，也可以使用选项形式。容器参数可以是容器名、工作区路径或 `.veil-link` 路径。

## 详细命令

### 初始化

`veil init <容器名称>` 创建容器、工作区、配置记录和链接。密码可以交互输入，也可以通过位置参数、`--password` 或 `VEIL_PASSWORD` 提供。

初始化还支持以下选项：

| 选项 | 作用 |
| --- | --- |
| `--link <路径>` | 指定链接输出位置 |
| `--workspace <名称>` | 使用已注册的命名工作区，参数是名称而不是路径 |
| `--workspace-path <路径>` | 指定工作区根路径，并自动登记给当前容器 |
| `--dedicated` | 让 `--workspace-path` 指定的空目录只属于当前容器 |
| `--portable` | 把工作区放在链接所在卷，不能与工作区选项同时使用 |

当链接位于外部卷，或者显式使用 `--portable` 时，默认工作区会放在链接目录下的隐藏工作区中。

`--workspace` 与 `--workspace-path` 互斥；`--dedicated` 只应与 `--workspace-path` 配合使用。相对路径会在初始化时固定为绝对位置，避免之后从其他目录解析链接时指向错误位置。

`default` 是自动补全的内置命名工作区；其他命名工作区必须已经存在于 `~/.veil/config.toml` 的 `workspace.custom` 映射中。当前 CLI 没有创建或注册自定义命名工作区的命令，因此自定义名称需要预先配置后才能使用。

`--workspace-path` 的“自动注册”只表示把实际容器根路径写入当前容器的 `workspace_path` 记录，方便链接丢失后恢复；它不会向 `workspace.custom` 新增命名工作区，因此之后不能通过另一个名称使用 `--workspace <名称>` 引用该路径。

### 添加文件

`veil add <容器> <源文件或目录>` 读取本地内容，加密后写入工作区，并更新 `.veil-meta`。

单文件可以使用位置目标路径或 `-o` 修改容器内名称。目录会递归导入，并保留相对目录结构；未指定目标时使用源目录名作为容器内前缀。同名目标采用替换语义，不会累积重复条目。错误密码会在写入任何密文前失败。

### 列出和查看

`veil list <容器>` 输出文件名称、大小、加密时间和总大小。

`veil free <容器>` 按原始相对路径构造真实父子目录树，并使用 `├──`、`└──`、`│` 绘制标准树状结构。文件和目录按名称排序，目录名带 `/`。

`veil info <容器>` 输出容器名称、稳定容器 ID、工作区路径、工作区类型、创建时间、文件数量、内容总大小、实际容器占用、MIME 类型分布和按虚拟路径排序的文件清单。

`veil exists <容器> <路径>` 判断容器内文件或隐式目录是否存在。文件或目录存在时退出码为 `0`，不存在时输出 `不存在` 并返回退出码 `1`，适合直接用于脚本判断：

```bash
if veil exists photos.veil-link vacation/photo.jpg -p 'password'; then
  echo "file exists"
fi
```

### 导出文件

`veil ex <容器> <容器内路径> <输出路径>` 解密指定文件并写入本地路径。输出路径是必填项。

当前 CLI 按精确虚拟路径查找单个文件。虽然帮助文本保留了通配符描述，但当前命令层调用的是单文件导出接口。

### 删除和重命名

`veil rm <容器> <容器内路径>` 删除文件，或递归删除目录内的全部文件。路径会进行容器内规范化，支持 `./tree` 这类写法；容器根目录和 `..` 路径逃逸会被拒绝。删除时会先提交更新后的元数据，再清理失去引用的密文。

`veil mv <容器> <原路径> <新路径>` 修改 `.veil-meta` 中的原始路径。文件可以重命名或移动到已有目录；目录移动时会同步更新全部子文件路径前缀。该操作不会移动或重命名磁盘上的随机加密文件名，也不会重新加密文件内容。

目标已经存在时拒绝覆盖；目录不能移动到自身或子目录。源路径和目标路径都会进行容器内规范化，支持 `./tree` 这类写法。

### 修改密码

`veil passwd <容器>` 使用旧密码解密容器，再用新密码重新加密元数据和所有文件。

位置参数形式为旧密码、新密码；选项形式使用 `--password` 和 `--new-password`。工作区中的每个文件都有自己的 nonce，密码修改不能只更新一个头部字段。

### 交互式 shell

`veil shell <容器>` 验证密码后进入交互循环。当前支持：

| 会话命令 | 作用 |
| --- | --- |
| `ls` 或 `list` | 列出文件 |
| `info` | 显示容器信息 |
| `add <文件>` | 添加文件 |
| `rm <文件>` | 删除文件 |
| `ex <文件> <输出>` | 导出文件 |
| `help` | 显示会话帮助 |
| `exit`、`quit` 或 `q` | 退出 |

Shell 不缓存派生密钥。每次文件操作仍由 `WorkspaceManager` 读取并解密必要的元数据或文件，因此它主要提供操作便利，不应被描述为批量操作的性能缓存。

## 打包与解包

`veil pack <容器>` 把工作区的加密元数据和已有密文写入单个 `.veil` 文件。默认输出名是 `<容器名>.vault.veil`，可用 `--output` 覆盖。

打包阶段不重新加密文件内容。输出文件已经存在时，命令会拒绝覆盖。

打包先写入同目录临时文件，全部数据和头部校验完成后才原子替换目标路径，中途失败不会留下损坏的 `.veil` 包。

`veil unpack <文件.veil>` 读取包内元数据，分配新的工作区目录，并在密码验证通过后重建 `.veil-meta`、容器配置和链接。密码错误、包损坏、路径不安全或配置写入失败时，会清理新建目录、链接和半成品文件。

常用选项如下：

| 选项 | 作用 |
| --- | --- |
| `--name <名称>` | 指定解包后的展示名称 |
| `--workspace <名称>` | 指定命名工作区 |
| `--link <路径>` | 指定新链接位置 |
| `--password <密码>` | 提供容器密码 |

## 配置与提示

`veil config` 或 `veil config show` 显示配置文件路径、有效提示级别、默认工作区、自定义工作区及容器、卷、链接数量。`veil config --hints full|brief|off` 修改提示级别。

提示级别也可以通过 `VEIL_HINTS` 临时覆盖。`full` 显示全部提示，`brief` 只保留关键恢复和解包提示，`off` 关闭提示。

全局配置位于 `~/.veil/config.toml`，主要内容包括：

| 配置项 | 说明 |
| --- | --- |
| 工作区 | 默认工作区和命名工作区路径 |
| 容器记录 | `veil_id`、展示名称、目录名和链接列表 |
| 卷记录 | 卷 ID、标签、挂载路径和最近探测时间 |
| 链接缓存 | 链接原始字节副本、哈希和状态 |
| 用户偏好 | 提示级别等设置 |

部分偏好字段已经保留在配置模型中，但当前 CLI 行为不会读取全部字段。

## 链接管理

`veil link <容器或工作区>` 生成新的 `.veil-link`。如果已有链接，命令会复制原文件并缓存其字节；如果容器已经登记但没有链接，则按配置重新生成；如果只能定位到工作区，则从 `.veil-meta` 明文头部读取容器身份。输出会按需创建父目录，必须以 `.veil-link` 结尾；配置缓存失败时会删除刚写出的链接。

多个链接可以指向同一工作区，因此通过任一链接执行的写操作都会影响同一份元数据和文件。

配置中存在链接原始字节时，缺失链接可以在后续解析过程中自动恢复。恢复后仍会校验内容哈希。

## 密码输入顺序

命令按以下顺序尝试获取密码：

1. 命令行参数或对应选项。
2. `VEIL_PASSWORD` 环境变量。
3. 当前终端交互输入。

新建容器或修改密码时，交互模式要求输入两次。参数和环境变量方式会跳过二次确认。

`veil passwd` 的旧密码使用 `VEIL_PASSWORD`，新密码使用 `VEIL_NEW_PASSWORD`。未设置新密码环境变量时进入交互输入，避免把旧密码静默复用为新密码。

命令行密码可能进入 shell 历史或进程参数列表。需要自动化的场景优先使用环境变量或受控的调用环境。

## 输出与本地化

CLI 默认输出中文，也可以通过 `VEIL_LANG` 选择语言。当前资源包含中文和英文。

Windows 控制台会根据输出代码页转换提示文字；Unix 平台按 UTF-8 输出。文件内容始终按二进制处理，不参与终端编码转换。

`veil help files` 显示各文件扩展名和容器文件的用途说明；`veil help <命令>` 可直接显示对应子命令帮助。`veil help all` 或 `veil help --all` 会输出顶层帮助以及全部子命令帮助。

### 错误码与退出码

所有错误统一输出为：

```text
❌ 错误 [1002]: 参数冲突: [密码] 不能与 --password <密码> 同时使用
```

错误码范围：

| 范围 | 含义 | 默认退出码 |
| --- | --- | --- |
| `1000-1999` | 命令行参数错误 | `2` |
| `2000-2999` | 密码错误 | `1` |
| `3000-3999` | 文件添加错误 | `1` |
| `4000-4999` | 配置错误 | `1` |
| `5000-5999` | `init` 初始化错误 | `1` |
| `6000-6999` | 链接错误 | `1` |
| `7000-7999` | 导出、打包和解包错误 | `1` |
| `8000-8999` | 帮助命令错误 | `1` |
| `9000-9999` | 底层核心错误和未分类异常 | `1` |

错误码和模板参数由统一的 `CommandError` 保存，最终由 CLI 边界按当前语言渲染。

## 并发与一致性

同一工作区的操作没有跨进程写锁。两个进程同时修改同一容器时，后写入的元数据可能覆盖先前修改。

不同容器可以使用不同工作区或不同容器目录，彼此没有共享写状态。应用需要在同一进程内并发访问容器时，应由上层显式提供锁和生命周期管理。

## 测试

CLI 测试位于 `crates/veil-cli/tests`，覆盖初始化、链接、配置、打包解包、密码修改、文件增删导出和 shell 会话。运行全部 workspace 测试使用 `cargo test --workspace --all-targets`。

## 当前限制

- `ex` 当前只处理单文件。
- `shell` 不提供密钥或容器对象的长期缓存。
- 同一工作区没有并发写锁。
- `passwd` 会重新加密全部工作区文件。
- 链接依赖稳定的卷身份和相对路径。
- 忘记密码后没有恢复通道。
