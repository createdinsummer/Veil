# Veil Core

`veil-core` 提供 Veil 的加密存储、目录索引、配置、链接和工作区操作。CLI 只负责用户交互与流程编排，磁盘格式、密码派生、内容加解密和恢复逻辑都在本库中实现。

## 文档边界

本文负责库层模型、模块职责、磁盘格式和一致性语义。具体命令参数和用户流程见 [CLI 文档](../veil-cli/README.md)。修改格式或存储流程时，应同时确认这里的约束是否仍然成立，再更新相应模块的 Rust 文档注释。

## 存储模型

核心库包含两套并行存在的存储能力。

### 工作区模型

工作区是 CLI 当前使用的默认模型。一个容器对应一个目录，目录中保存：

| 文件 | 作用 |
| --- | --- |
| `.veil-meta` | 明文恢复头部和加密 JSON 元数据 |
| `<随机 ID>.enc` | 单个文件的独立密文 |

`WorkspaceManager` 提供初始化、读取元数据、添加、导出、删除、重命名和修改密码等操作。元数据保存稳定 `veil_id`、展示名称、工作区类型、创建时间和文件清单。

### 单文件容器模型

`container` 和 `format` 模块提供单文件容器读写。该模型把文件 blob、目录索引和头尾信息组织在同一个文件中，使用 x25519 与 age 完成内容加密。

CLI 的 `pack` 命令使用另一套 `container_format` 打包器，把工作区中的加密元数据和已有密文封装为一个 `.veil` 文件。两种 `container` 命名接近，但对应不同的磁盘布局和调用路径。

## 工作区元数据

`.veil-meta` 由两部分组成：

1. 明文 TLV 头部，包含魔数、头部长度、版本、盐值、nonce、算法标识、`veil_id`、容器名称和工作区类型。
2. 使用主密钥加密的 JSON 元数据，包含完整文件清单和创建时间等字段。

文件条目保存加密文件名、相对原始路径、明文大小、nonce、加密时间和可选哈希。原始路径始终相对于容器根目录，不保存宿主机绝对路径。

工作区密码通过 Argon2id 派生主密钥。当前文件内容加密路径使用 ChaCha20-Poly1305，每个文件生成独立 nonce。修改工作区密码时，需要重新加密元数据和全部文件。

## 单文件容器格式

`format` 模块定义的单文件容器由以下区域顺序组成：

| 区域 | 内容 |
| --- | --- |
| Header | 魔数、版本、KDF flags、CLI 版本和受保护的 x25519 私钥 |
| Blob 区 | 每个文件各一段完整 age STREAM 密文 |
| Index | 序列化后再加密的嵌套目录树 |
| Footer | Index 偏移、Index 长度和固定结束魔数 |

Header 中的私钥使用用户密码保护。密码经 Argon2id 派生对称密钥，再通过 ChaCha20-Poly1305 加密私钥文本。文件 blob 和 Index 使用容器公钥加密，读取时由已解出的 x25519 私钥解密。

提交目录树时，`commit` 把新的 Index 和 Footer 追加到文件末尾，并同步文件。打开容器时先读取文件尾 Footer；如果尾部存在未完成数据，则向前扫描有效 Footer，并在恢复成功后截断未提交区域。

## 工作区打包格式

`ContainerPacker` 和 `ContainerUnpacker` 处理 CLI 的 `pack` 与 `unpack`。

包文件以固定 22 字节头部开始，记录魔数、版本、头部长度、元数据长度和文件数量。头部之后依次保存工作区 `.veil-meta` 的完整加密字节，以及若干文件条目。每个文件条目包含原始路径、密文长度和对应密文。

打包不重新加密文件内容。解包后需要密码解密元数据，再根据文件清单把原始名称重命名为工作区使用的随机加密名称。

## 路径与索引

`index` 使用 `BTreeMap` 表示按名称排序的嵌套目录树。路径由节点位置隐含，不重复保存完整字符串。

支持的路径操作包括插入或覆盖文件、按路径查询、删除文件、清理变空目录、递归列出文件以及 glob 模式匹配。匹配选项要求 `*` 不跨目录，`**` 可以跨目录。

`slice_reader` 把底层 reader 限定在 `[start, start + len)` 区间。读取不会越过 blob 边界，定位使用区间内坐标，适合把单个 blob 直接交给解密器。

## 链接与卷

`.veil-link` 保存稳定 `veil_id`、展示名称、目标卷 ID、卷标签和工作区相对路径。链接不保存密码或文件内容。

解析链接时先识别链接当前所在卷。只有链接所在卷与记录中的卷 ID 一致，或者调用方提供了可信挂载路径，才能拼出工作区绝对路径。

Unix 使用文件系统设备号识别卷，并把路径归约到同一设备的根目录。Windows 使用盘符作为卷键。外部卷判断只用于工作区布局和提示，不参与加密身份。

## 临时明文

`TempPlaintext` 是临时文件的 RAII 守卫。对象离开作用域时自动删除文件，避免调用方在错误路径或提前返回时遗漏清理。

Linux 优先使用 `/dev/shm`，其他平台使用系统临时目录。Unix 文件以 `0600` 创建，并通过 `create_new` 避免覆盖已有文件。删除是尽力而为，在 SSD 等介质上不承诺物理擦除。

## 错误与返回值

`VeilError` 区分 I/O、容器格式、配置、工作区、序列化、密钥派生和加解密错误。模块通过 `Result<T>` 返回可处理的错误，CLI 再把错误转换为本地化消息。

格式解析会拒绝错误魔数、不支持版本、未知 KDF、无效 UTF-8 和缺失必需字段。涉及长度字段的解析路径应保持边界检查，避免读取不完整输入。

## 并发与一致性

库中没有为同一容器提供跨线程或跨进程写锁。`WorkspaceManager` 的更新流程是读取元数据、修改、再写回，两个并发写操作可能覆盖彼此的变更。

不同容器可以并行操作。需要在同一进程内共享容器状态时，锁、缓存和生命周期管理应由上层应用负责。

单文件容器采用追加提交和 Footer 恢复来保护已提交数据。工作区元数据使用同目录临时文件加重命名替换，但工作区文件写入、元数据更新和跨进程并发不构成事务。

## 依赖

核心库当前使用的主要依赖包括：

| 依赖 | 用途 |
| --- | --- |
| `age` | x25519 信封、blob 和索引加密 |
| `argon2` | 密码到主密钥的派生 |
| `chacha20poly1305` | 私钥封装和工作区内容加密 |
| `blake3` | 单文件内容和完整性校验 |
| `serde`、`serde_json` | 元数据和链接模型 |
| `postcard` | 单文件目录树序列化 |
| `toml` | 全局配置和链接文件 |
| `glob` | 虚拟路径模式匹配 |
| `zeroize` | 敏感内存清理 |

## 测试

单元测试覆盖密钥、格式、索引、流式读取、临时文件和单文件容器。集成测试覆盖单文件容器的创建、读写、删除、重命名、密码修改、崩溃恢复和完整性损坏检测。工作区测试覆盖初始化、文件增删导出和密码校验。

运行方式为 `cargo test -p veil-core --all-targets`，完整 workspace 测试使用 `cargo test --workspace --all-targets`。

## 当前限制

- 工作区模型没有跨进程写锁。
- 工作区密码修改需要重新加密全部文件。
- `container_format` 解包使用固定大小条目头缓冲区，条目名称头必须能装入该缓冲区。
- 单文件工作区的删除会留下未引用的密文空间，当前没有 compaction 命令。
- MIME 识别只看扩展名，不读取文件内容。
- 全局配置中包含部分尚未参与运行时行为的偏好字段。
