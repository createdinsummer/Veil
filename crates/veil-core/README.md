# Veil Core

`veil-core` 提供 Veil 的加密存储、文件清单、打包格式、配置、链接和 Work 管理。CLI 只负责用户交互与流程编排，磁盘格式、密码派生、内容加解密和恢复逻辑都在本库中实现。

## 文档边界

本文负责库层模型、模块职责、磁盘格式和一致性语义。具体命令参数和用户流程见 [CLI 文档](../veil-cli/README.md)。修改格式或存储流程时，应同时确认这里的约束是否仍然成立，再更新相应模块的 Rust 文档注释。

## 存储模型

日常读写使用 Work/Veil 目录模型，备份和迁移使用 `.veil` 打包文件。两者共用元数据和文件密文。

### Work / Veil 模型

CLI 当前使用 Work 组织 Veil。Work 对应一个 `work_root`；每个 Veil 对应一个实际目录 `veil_dir`，其中保存：

| 文件 | 作用 |
| --- | --- |
| `.veil-info` | 明文恢复头部和加密 JSONC 元数据 |
| `<随机 ID>.enc` | 单个文件的独立密文 |

本机配置固定在 `~/.veil/config.jsonc`，移动盘配置固定在 `<盘根目录>/.veil/config.jsonc`。各配置只管理自身工作区，不保存卷 ID 或挂载位置。程序枚举实际挂载的外部卷，跳过没有配置的盘，发现过程不创建配置或目录。

Work 配置保留 `path`、类型、说明和创建时间。相对路径始终基于所属配置文件的目录解析；默认值 `works/default` 分别指向 `~/.veil/works/default` 或 `<盘根目录>/.veil/works/default`。工作区没有独立身份文件。所有容器目录为 `work_root/veil_id`；默认工作区和自定义工作区允许多个容器，专属工作区只允许一个容器。

`VeilManager` 提供初始化、读取元数据、添加、导出、删除、重命名和修改密码等操作。元数据保存稳定 `veil_id`、展示名称、创建时间和文件清单。

### 打包与迁移

`veil_package` 把 `veil_dir` 中的元数据和已有密文封装为一个 `.veil` 文件。包文件用于备份和迁移，先解包为目录后再进行文件增删、导出或密码修改。

旧独立单文件格式已经移除。若已有这类数据，应使用支持旧格式的历史版本导出内容，再导入当前目录模型；已有 `pack` 打包文件继续使用原格式。

## Veil 元数据

`.veil-info` 由两部分组成：

1. 明文 TLV 头部，包含魔数、头部长度、版本、盐值、本次提交的 nonce、算法标识、`veil_id`、`veil_name` 和容器创建时间。
2. 使用密码保护密钥加密的 JSONC 元数据，包含完整文件清单、数据主密钥和创建时间等字段。

当前 Veil 元数据格式版本为 6。项目不提供旧版本元数据迁移，旧格式数据需要重新创建。

文件条目保存稳定 `file_id`、加密文件名、相对原始路径、明文大小、nonce、加密时间和可选哈希。原始路径始终相对于 `veil_dir`，不保存宿主机绝对路径。

Veil 通过 Argon2id 从密码和 salt 派生密码保护密钥，元数据中保存一把或两把随机数据主密钥。文件内容使用当前数据主密钥分块加密，每块独立进行 ChaCha20-Poly1305 认证；元数据 JSONC 则使用密码保护密钥加密。每次元数据提交都生成新的 nonce，不复用同一密钥下的 AEAD nonce。

每个文件保存一个随机 12 字节 base nonce。实际分块 nonce 由 base nonce 和块序号经过 BLAKE3 派生，AAD 绑定块序号。文件按 1 MiB 明文块进行流式加密、解密和完整改密重写，内存占用不随文件大小增长。元数据中的文件大小决定分块数量和最后一块明文长度。

`file_ops::rewrite_file_streaming` 接受旧数据主密钥、新数据主密钥、旧路径、新路径、两侧 base nonce 和明文大小；它在一次单遍读取中完成“旧分块解密、新分块加密、目标文件写入”，并通过同目录临时文件和原子替换发布新密文。

默认修改密码只生成新的 salt、密码保护密钥和元数据 nonce，并原子替换 `.veil-info`，现有 `.enc` 文件完全不变。完整改密会在元数据中暂时同时保存新旧数据主密钥，逐个重新加密文件；每个文件提交后读取端优先尝试新数据主密钥，失败时回退旧数据主密钥。迁移期间旧密码继续有效，中断后可再次执行完整改密继续；全部迁移完成后才切换到新密码并删除旧数据密钥。

## Veil 打包格式

`VeilPacker` 和 `VeilUnpacker` 处理 CLI 的 `pack` 与 `unpack`。

包文件以固定 22 字节头部开始，记录魔数、版本、头部长度、元数据长度和文件数量。头部之后依次保存 `.veil-info` 的完整原始字节（明文头部与加密 JSONC），以及若干文件条目。每个文件条目包含明文原始路径、密文长度和对应密文。

打包不重新加密文件内容。解包后需要密码解密元数据，再根据文件清单把原始名称重命名为 `.enc` 随机名称。

`VeilUnpacker::read_password_verifier` 只读取一次包内元数据，返回可跨线程共享的 `VeilPasswordVerifier`。候选密码通过与解包流程相同的 Argon2id 派生、AEAD 认证和 JSONC 解析进行验证，不解包、不读取文件内容。

## 路径与文件清单

`MetaData::files` 保存扁平的文件条目列表，通过每个条目的 `original_name` 表达目录层级。`VeilManager` 支持精确路径导出、递归删除、目录移动和同路径替换；路径规范化会拒绝 `..` 逃逸和非法根目录操作。

## 链接与寻址

配置和 `.veil-link` 均使用 JSONC，支持行注释、块注释和尾逗号；更新保留未删除字段的注释与排版。

`.veil-link` 顶层仅包含 `version`、链接创建时间 `created_at` 和 `veil`。`veil` 仅包含容器 `veil_id`、展示名称 `veil_name` 和原始创建时间 `created_at`，信息来自 `.veil-info`。链接不保存卷、工作区或位置。配置中 `links[].link` 直接复用 `VeilLink`；外层保存链接文件路径、观察状态和观察时间。

所有普通入口（ID、名称、链接）统一遍历本机配置与已挂载移动盘配置登记的工作区。按 ID 逐一检查 `work_root/veil_id`，读取 `.veil-info` 明文头核验 ID 和目录名；按名称扫描容器明文头。唯一匹配才返回；同名容器提示使用 ID，同 ID 的不同副本报告歧义。重复登记同一个实际目录不会产生副本歧义。容器缓存不参与位置查找，缓存记录不占用已不存在的容器 ID。

容器可以整体移动到任一已登记工作区或移动盘，保留 ID 目录、`.veil-info` 和所有 `.enc` 文件即可。原链接保持有效，不需要修改链接或重新加密。移动盘配置使用相对路径时，换电脑或挂载点变化后仍可发现容器；未挂载时报未找到，不创建替代容器。解包保留包内 ID，发现在线的同 ID 容器时拒绝覆盖。

缺失链接仅在缓存正文有效且目标容器唯一可用时恢复。配置和链接丢失后，可用 `veil link <work_root/veil_id>` 从明文头重建链接并登记父工作区。普通命令不直接接受容器目录。`VeilManager::for_veil` 绑定已确认的 ID，后续元数据操作继续核验身份。

## 临时明文

`TempPlaintext` 是临时文件的 RAII 守卫。对象离开作用域时自动删除文件，避免调用方在错误路径或提前返回时遗漏清理。

Linux 优先使用 `/dev/shm`，其他平台使用系统临时目录。Unix 文件以 `0600` 创建，并通过 `create_new` 避免覆盖已有文件。删除是尽力而为，在 SSD 等介质上不承诺物理擦除。

## 错误与返回值

`VeilError` 区分 I/O、格式、配置、Work、序列化、密钥派生和加解密错误。模块通过 `Result<T>` 返回可处理的错误，CLI 再把错误转换为本地化消息。

格式解析会拒绝错误魔数、不支持版本、无效 UTF-8 和缺失必需字段。打包元数据的解密入口还会拒绝不支持的加密算法和不完整认证数据。涉及长度字段的解析路径保持边界检查，避免读取不完整输入。

## 并发与一致性

当前实现未定义同一 Veil 的跨进程并发写入语义。不同 Veil 使用不同 `veil_dir` 时彼此没有共享状态，可以在不同进程中分别操作。

Work 模型采用不可变密文加元数据快照：新密文先写入并同步文件及目录，随后 `.veil-info` 通过同目录临时文件原子替换。只有当前元数据再次确认持久化后，程序才删除失去引用的旧密文；崩溃遗留的临时文件和孤立密文会在下一次成功解密元数据时清理。

默认改密只重保护元数据，不触碰文件密文。完整改密采用写时复制，并在迁移期间保留新旧数据主密钥，不会原位覆盖旧密文。因此进程在任一阶段被终止时，磁盘上的每个文件都能用当前密钥或回退密钥读取，不会出现无法判断密钥归属的密文。

## 依赖

核心库当前使用的主要依赖包括：

| 依赖 | 用途 |
| --- | --- |
| `argon2` | 密码到密码保护密钥的派生 |
| `chacha20poly1305` | 元数据加密和分块内容加密 |
| `blake3` | 分块 nonce 派生和链接缓存摘要 |
| `serde`、`serde_json` | 数据模型和 JSONC 序列化 |
| `jsonc-parser` | JSONC 解析及保留注释的配置、链接更新 |
| `zeroize` | 敏感内存清理 |

## 测试

单元测试覆盖元数据、分块内容加解密、临时文件、链接和配置。集成测试覆盖初始化、文件增删导出、密码修改、完整改密恢复，以及打包格式的缓存密码验证、损坏元数据和旧格式拒绝。

运行方式为 `cargo test -p veil-core --all-targets`，完整工程测试使用 `cargo test --workspace --all-targets`。

## 当前限制

- 同一 Veil 的跨进程并发写入语义尚未实现。
- 完整改密需要逐个重新加密全部文件；默认改密只重新保护元数据。
- `veil_package` 解包使用固定大小条目头缓冲区，条目名称头必须能装入该缓冲区。
- MIME 识别只看扩展名，不读取文件内容。
