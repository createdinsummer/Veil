# SQLite 数据存储改造设计与开发清单

日期：2026-10-28。状态：SQLite 存储改造已实现；移动端验证及 Windows、Linux 实机运行尚未完成。

本文整理已经确认的存储边界、八张表、执行身份、文件级并发、密钥轮换和实施顺序。后续开发以本文的目标行为为准，不将讨论中已经替换的早期方案重新引入实现。

## 1. 目标与范围

| 层级 | 保存位置 | 职责 |
| --- | --- | --- |
| 本机应用数据库 | 当前设备的应用数据目录 | 空间信息、空间与容器登记、用户设置、系统设置、本地记录 |
| 容器数据库 | 每个容器自己的目录 | 容器身份、目录树、文件信息、内容版本链、文件加密密钥、运行锁 |
| 文件密文 | 对应容器目录中的独立文件 | 文件内容，通过流式读写处理，不能整体塞入数据库 |

确定的边界：

- 每个空间对应当前设备上的一个本地文件夹，容器目录位于所属空间中。
- 空间 ID、容器 ID、节点 ID 是稳定身份，名称或位置变化不改变身份。
- 本机应用数据库记录容器归属及展示缓存；容器数据库是容器身份与内容信息的权威来源。
- 容器数据库与文件密文一起迁移，使用容器密码即可独立打开，不依赖原设备的应用数据库。
- CLI、桌面端和移动端通过 `veil-service` 使用业务能力。
- `veil-core` 提供底层加密、流式文件操作、版本比较、执行身份和系统存活检查能力；`veil-service` 负责数据库业务访问与流程编排。
- 不使用应用层目录树缓存。执行模块自己的进程内生命周期登记簿继续保留。
- 不读取旧配置，不实现旧配置迁移，不为旧容器存储格式增加兼容分支。新格式应明确拒绝不支持的旧格式。
- 本次不实现云同步、密码本或外部目录授权扩展。

首期使用各平台的应用数据目录。桌面端与同一系统用户运行的 CLI 必须采用一致的目录定位策略；移动端先使用应用私有数据目录。平台适配层提供目录，service 统一初始化与访问。

建议文件布局：

```text
应用数据目录/Veil/
├── app.db                         本机应用数据库
└── spaces/
    └── <space_id>/                默认管理的空间文件夹
        └── <veil_id>/             容器目录
            ├── veil.db            SQLCipher 加密数据库
            ├── <随机名称>.enc     独立文件密文
            └── .staging/          写入暂存区，内容同样是密文
```

应用库文件名、默认管理目录名是首期实现约定；空间实际位置始终以 `space_info.local_path` 为准。SQLite 日志文件由数据库管理，不能自行删改。

## 2. 加密与解锁

### 2.1 数据库

- 本机应用库使用普通 SQLite 存储本机索引与配置，不能保存容器密码或文件加密密钥。
- 容器库使用 SQLCipher 的整库加密方式；不采用逐字段加密，也不额外保留一张明文业务表。
- 容器密码交给 SQLCipher 的原生密码派生流程处理；随机盐由 SQLCipher 保存在数据库文件头。
- 首期使用统一、固定的 SQLCipher 格式及派生参数，各平台必须一致，不能随库升级或平台变化而静默改变。
- 先设置数据库密钥及固定参数，再通过实际读取验证密码；仅仅打开连接或设置密钥未报错，不代表解锁成功。打开已有容器失败时不能悄悄创建替代数据库。
- 不为解锁单独增加配置文件，也不再将旧 `.veil-info` 作为元数据权威来源。
- 解锁前不依赖加密业务表中的 `schema_version`；该字段用于解锁后的业务结构升级，不是读取派生参数的入口。
- 不把解密后的 SQLite 文件写入磁盘再打开。容器数据库、数据库日志和可能的临时数据都必须遵守所选 SQLCipher 构建的加密要求。

SQLCipher 的数据库密码保护与文件内容加密是两层能力。数据库密码派生不再直接套用现有元数据的 Argon2id 流程；现有文件流式加密格式继续复用。不得把 SQLCipher 的数据库密钥和 `div_info.data_keys` 中的文件数据密钥混为一类。

### 2.2 未解锁时的识别

- 已登记的容器通过本机的容器 ID、所属空间、名称缓存、链接缓存展示和定位。
- 这些缓存不代表已验证容器内容，也不决定文件清单或文件版本。
- 解锁后核对实际 `veil_id`，并刷新本机缓存。身份不一致或出现同 ID 的多个实际副本时报告冲突，不能任意选择一个副本。
- 新设备或缓存丢失时，允许通过目录位置及用户输入的密码重新登记容器。
- `.veil-link` 仍是便携入口，正文缓存进入 `local_record`。本机缓存足够时可恢复链接；缓存不足时先解锁读取所需身份信息，不再依赖旧明文头。

## 3. 字段和约束的共同约定

| 类型 | 约定 |
| --- | --- |
| 稳定 ID、名称 | `TEXT`；主键与必填身份字段显式设置 `NOT NULL` |
| 时间 | UTC 毫秒，`INTEGER` |
| 顺序、大小、结构版本 | `INTEGER`；大小与顺序不得为负，结构版本为正数 |
| JSON | `TEXT`；通过类型化模型读写并校验，不能把非法 JSON 当默认值覆盖 |
| nonce | `BLOB`；按现有文件加密格式校验长度 |

每条连接显式启用外键检查。写操作使用短事务，涉及先检查再修改的流程应在同一个写事务内完成。SQL 参数必须绑定，密码与密钥材料不能拼接到 SQL 或写入日志。

结构版本升级属于数据库内部能力，不增加新的业务分类。实现时统一处理初始化、版本检查和升级事务，禁止各业务模块自行补表。

## 4. 本机应用数据库：五张表

### 4.1 `space_info`：空间信息

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| `id` | TEXT，主键 | 空间稳定 ID |
| `name` | TEXT，非空 | 空间展示名称 |
| `description` | TEXT，可空 | 空间说明 |
| `local_path` | TEXT，可空 | 本设备绑定的空间文件夹位置 |
| `storage_mode` | TEXT，非空，默认 `shared` | `shared` 可放多个容器；`dedicated` 只允许一个容器 |
| `sort_order` | INTEGER，非空，默认 `0` | 空间排列顺序 |
| `created_at` | INTEGER，非空 | 创建时间 |
| `updated_at` | INTEGER，非空 | 最后修改时间 |

- 本机创建空间时必须绑定目录；未来从其他设备同步来的空间可暂未绑定本机目录。
- 改名不改变空间 ID，不改变容器归属。
- 默认空间由 `system_setting.default_space_id` 引用，不增加 `is_default`，不把文本 `default` 当作稳定 ID。
- 不能在同一设备把同一个实际目录登记成多个独立空间。路径解析须消除可确认的目录别名，不能只比较用户输入字符串。
- `local_path` 是本机字段，未来不能随空间逻辑信息覆盖到其他设备。

### 4.2 `space_div`：空间与容器登记

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| `div_id` | TEXT，主键 | 对应容器库的 `div_info.veil_id` |
| `space_id` | TEXT，非空，外键 | 引用 `space_info.id` |
| `cached_name` | TEXT，非空 | 容器名称展示缓存 |
| `sort_order` | INTEGER，非空，默认 `0` | 空间内排列顺序 |
| `registered_at` | INTEGER，非空 | 本机登记时间 |
| `updated_at` | INTEGER，非空 | 登记记录修改时间 |

- 一个容器只登记在一个空间中。初始索引至少覆盖按 `space_id` 列出容器的查询。
- `div_id` 是跨数据库的逻辑引用，不能声明为对另一份数据库的普通外键。
- `dedicated` 空间的数量检查与登记操作必须在同一个写事务中完成。
- 在本机的容器目录通过所属空间位置与容器 ID 解析，不重复维护独立绝对路径字段。
- 移动容器由 service 编排磁盘操作与登记更新，不能只修改 `space_id` 就报告成功。
- 取消登记与删除实际数据是不同操作，不能用外键级联代替磁盘删除流程。

### 4.3 `user_setting`：用户偏好

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| `key` | TEXT，主键 | 偏好项名称 |
| `value_json` | TEXT，非空 | JSON 格式的值 |
| `updated_at` | INTEGER，非空 | 最后修改时间 |

初期设置项示例：

| key | 值示例 | 用途 |
| --- | --- | --- |
| `hint_level` | `"full"` | 提示级别；允许 `full`、`brief`、`off` |
| `layout` | `"grid"` | 网格或列表布局 |
| `view_mode` | `"type"` | 按类型或按路径展示 |
| `unlock_cache_seconds` | `3600` | 解锁成功后密码在客户端内存中的保留秒数；`0` 表示关闭，上限 86400。旧库缺少该项时补为 3600；密码本身不进入数据库 |

可用 key、值类型、默认值和允许范围由 service 统一定义与校验。未来可以同步选定的用户设置项，不把整库复制视为设置同步。

### 4.4 `system_setting`：本机系统设置

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| `key` | TEXT，主键 | 设置项名称 |
| `value_json` | TEXT，非空 | JSON 格式的值 |
| `updated_at` | INTEGER，非空 | 最后修改时间 |

| key | 用途 |
| --- | --- |
| `device_id` | 当前安装实例的持久身份，不能使用 PID 代替 |
| `default_space_id` | 本设备的默认空间，service 校验其引用有效性 |

本表只保存本机应用设置，不参与用户偏好同步。设备身份在进程重启后保持不变；进程身份则随进程实例变化。

### 4.5 `local_record`：本机状态与缓存

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| `record_type` | TEXT，非空，联合主键 | 记录类型 |
| `record_key` | TEXT，非空，联合主键 | 类型内唯一标识 |
| `value_json` | TEXT，非空 | JSON 格式的记录内容 |
| `updated_at` | INTEGER，非空 | 最后修改时间 |

主键为 `(record_type, record_key)`。最近访问查询可通过 `(record_type, updated_at, record_key)` 索引优化；使用实际查询计划验证。

| record_type | record_key | 内容 |
| --- | --- | --- |
| `recent_div` | 容器 ID | 最近访问记录 |
| `link_cache` | 本机链接位置 | `.veil-link` 的完整结构化正文 |
| `space_access` | 空间 ID | 平台目录访问授权引用，首期应用目录通常不需要 |
| `hint_state` | 提示标识 | 提示是否已展示 |
| `div_state` | 容器 ID | 最近观察到的可用状态 |

同类记录的同一目标只维护一条。本表不是逐次追加的操作日志，不重复保存 `space_info.local_path`。缓存失效或目录不可用不能直接解释为容器数据已删除。

## 5. 容器数据库：三张表

### 5.1 `div_info`：容器信息

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| `id` | INTEGER，主键，固定为 `1` | 只有一条记录 |
| `veil_id` | TEXT，非空，唯一 | 容器稳定 ID |
| `name` | TEXT，非空 | 容器名称的权威记录 |
| `created_at` | INTEGER，非空 | 容器原始创建时间 |
| `schema_version` | INTEGER，非空 | 业务表结构版本 |
| `data_keys` | TEXT，非空，JSON | 文件数据密钥集合与轮换状态 |

`data_keys` 的每项保存 `key_id`、`key_material`、`status`、`created_at`。二进制密钥按统一编码序列化；密钥集合本身由整库加密保护，不得复制到本机应用库或日志。

- 正常状态只有一把 `active` 文件密钥。
- 完整改密期间允许一把 `active` 新密钥及一把 `retiring` 旧密钥，最多两把。
- 已处于双密钥状态时恢复未完成的轮换，不能再次生成第三把密钥。
- 新写入使用当前活动密钥；旧密钥仍被引用时不能移除。

### 5.2 `file_info`：目录树、文件信息与内容版本链

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| `id` | TEXT，主键 | 稳定的目录节点或文件节点 ID |
| `parent_id` | TEXT，可空，外键 | 引用本表的父目录 ID |
| `name` | TEXT，NOT NULL | 当前节点名称，不保存完整路径；只有根节点允许空字符串 |
| `kind` | TEXT，非空 | `directory` 或 `file` |
| `created_at` | INTEGER，非空 | 节点创建时间 |
| `updated_at` | INTEGER，非空 | 节点内容或名称、父关系的修改时间 |
| `cipher_name` | TEXT，可空，唯一 | 当前独立密文文件名 |
| `size` | INTEGER，可空 | 明文大小，非负 |
| `key_id` | TEXT，可空 | 引用 `div_info.data_keys` 中的文件密钥 |
| `nonce` | BLOB，可空 | 当前文件加密格式要求的 12 字节基础 nonce |
| `encrypted_at` | INTEGER，可空 | 当前密文生成时间 |
| `version_history` | TEXT，可空，JSON | 按顺序排列的内容版本 UUID |

结构约束：

- 一个容器只有一个根目录。只有根目录的 `parent_id` 为 NULL，根节点必须是目录；根节点名称允许为空。
- 非根节点的名称不能为空，不能使用 `.`、`..`，不能包含路径分隔符或 NUL。
- 父节点必须是目录；节点不能以自身或自身的后代为父节点。
- 建立 `(parent_id, name)` 唯一索引，同目录名称按一致的字符串比较规则校验。根目录唯一性需要单独约束，不能依赖 NULL 的联合唯一性。
- 目录的文件专用字段为 NULL；文件的对应字段必须存在并通过格式校验。
- `key_id` 引用 JSON 内的密钥项，由 service 校验，不伪造普通外键。
- 完整路径沿父节点组合，不额外维护一份权威完整路径，也不建立应用层目录树缓存。
- 改名或移动不改变节点 ID，不增加内容版本；重新加密不增加内容版本。
- 内容发生变化时追加新的版本 UUID，保留原有版本链。
- 版本链必须非空，成员是有效且不重复的版本 UUID。当前只保留内容继承关系，不承诺保留历史内容副本。

目录查询、按名称查子节点通过联合索引执行；查询祖先或全部后代使用递归查询。不得仅凭有索引就承诺整体性能，需用宽目录、深目录及大子树数据验证。

### 5.3 `operation_locks`：文件级运行锁

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| `lock_id` | TEXT，主键 | 锁记录 ID，可用于标识操作产生的暂存对象 |
| `resource_type` | TEXT，非空 | 资源类型；首期业务锁以文件为单位 |
| `resource_id` | TEXT，非空 | 文件节点稳定 ID；新文件可先分配 ID 再持锁 |
| `mode` | TEXT，非空 | `read` 或 `write` |
| `owner_identity` | TEXT，非空，JSON | 直接序列化现有 `ExecutionOwner` |
| `owner_endpoint` | TEXT，可空，JSON | 所属进程的本机查询端点及访问凭证 |
| `owner_token` | TEXT，非空 | 本次持锁凭证，不能与文件加密密钥混用 |
| `expires_at` | INTEGER，非空 | 租约到期时间 |

- 同一文件可以有多条不同持有者的读锁，不能对 `resource_id` 单独建立唯一约束。
- 初始索引至少支持 `(resource_type, resource_id, expires_at)` 的冲突查询。
- 锁记录是当前设备的运行状态，不进入业务同步；导出给新设备的业务快照不保留原设备的锁记录。
- 不再增加四级应用锁，也不使用额外锁文件实现这套业务锁协议。SQLite 自身的事务锁仍由数据库维护。

## 6. 执行身份与跨进程查询

本部分基础代码已经实现，后续复用现有接口，不重复造一套身份模型：

| 模块 | 已有职责 |
| --- | --- |
| [core 执行模块](../crates/veil-core/src/execution/mod.rs) | 统一身份、线程登记、同步任务作用域、阻塞任务包装、运行时无关的 Future 包装 |
| [core 系统检查](../crates/veil-core/src/execution/process.rs) | 检查其他进程实例；无法可靠判断时保持 Unknown |
| [service 执行模块](../crates/veil-service/src/execution/mod.rs) | 查询本进程身份、检查其他进程、委托对方进程查询其线程或任务、统一调度封装 |
| [service 本机通信](../crates/veil-service/src/execution/transport.rs) | 带随机访问凭证及进程实例校验的本机回环查询 |

`ExecutionOwner` 支持：

- `process`：`ProcessIdentity`。
- `thread`：进程实例及本进程生成的线程身份。
- `task`：进程实例及稳定任务身份。

进程身份包含 PID、随机进程实例 ID，以及可获取的操作系统进程实例标识，例如进程创建时间；部分平台的标识同时包含系统启动信息。Rust 的线程身份不作为系统 TID 使用。线程池中的线程与在线程池中执行的任务分别登记，任务结束不代表线程退出。

参与持锁的业务线程、阻塞任务及异步任务必须通过统一运行入口创建或包装。主线程及外部运行时线程通过适配入口登记，不要求改写第三方运行时内部的线程创建。

任务跨线程调度时身份不变。持锁归属由调用方明确选择；需要交接给另一个执行单元时显式操作，不随调度线程自动变更。

查询规则：

1. 查询本进程的线程或任务时，由本进程登记簿回答。
2. 查询其他进程的线程或任务时，先检查进程实例，再通过该进程的 service 查询其登记簿。
3. 只有确认原持有者已结束才返回 `Dead`。缺少登记记录、通信超时、权限不足或通信响应身份不匹配均返回 `Unknown`。操作系统确认原进程实例已退出、即使 PID 已被复用，也可以返回 `Dead`。
4. 控制入口读取登记簿，不向繁忙的工作线程发 ping。
5. 确认整个持有进程退出后，可以回收其所属线程与任务的锁，无需继续请求已经退出的进程。
6. 移动端被挂起时可能无法响应或续租；恢复执行前必须重新校验凭证和租约。

## 7. 文件级并发与版本控制

### 7.1 冲突矩阵

以下规则针对同一文件：

| 已持有 | 新申请读锁 | 新申请写锁 |
| --- | --- | --- |
| 无锁 | 允许 | 允许 |
| 读锁 | 允许 | 等待或返回忙 |
| 写锁 | 等待或返回忙 | 等待或返回忙 |

不同文件的流式加密或读取可以并行；元数据提交仍服从 SQLite 单写事务规则。禁止为长时间加密持续占有数据库写事务。

### 7.2 申请、续租、释放与归属交接

- 申请锁使用短写事务，原子地处理失效记录、检查冲突和插入锁记录；不能先检查再在另一个事务中插入。
- 一次需要多个文件锁时，统一排序并尽可能在一个短事务中批量申请；失败后不能留下部分持锁且无限等待其他资源。
- 确认持有进程或持有线程、任务结束时，允许无视 `expires_at` 提前回收。
- 无法确认存活状态时按租约处理；进程还活着也不能为其所有历史任务无条件续租。
- 续租、释放、转移及最终写入，都必须校验当前 `owner_token`。过期凭证不能续活，必须重新申请。
- 交接必须显式发起，在短事务内更改身份、查询端点及凭证。旧凭证立即失效；一组关联锁必须整体交接。
- 取消请求或丢弃等待句柄不代表实际工作已停止，尤其不能提前释放仍在执行的阻塞任务的锁。
- 等待必须支持超时与取消。等待期限采用单调计时；系统时间变化不能导致无限等待或绕过提交校验。
- 租约期限、续租间隔和等待退避由 service 集中定义，并通过挂起、时钟变化和并发测试验证，不能散落在各客户端。

### 7.3 版本链

保存已有文件时，调用方携带读取时的容器 ID、文件 ID 与基础版本链。最终提交必须在同一事务中检查：

1. 节点仍存在且为原文件身份。
2. 当前内容版本链与基础版本链一致。
3. 写锁凭证仍有效。
4. 新密文使用的密钥仍是允许提交的当前活动密钥。

版本已更新、分叉、无共同起点或身份变化时拒绝覆盖。不能用版本链长度猜测新旧，不能因为拿到了写锁就忽略基础版本校验。

## 8. 数据库与文件的一致性

**数据库是权威来源。** 文件的存在不等于文件已经提交，磁盘扫描不能反向覆盖数据库中的文件清单或版本链。

### 8.1 写入或覆盖文件

1. 校验目标目录与基础版本，分配稳定文件 ID，获取文件写锁。
2. 使用当前活动文件密钥，流式写入全新的随机命名密文，不能原地覆盖旧密文。
3. 持久化新密文及必要的目录项。
4. 开启短写事务，重新校验节点、父目录、版本链、密钥状态和持锁凭证。
5. 更新 `file_info` 的当前密文引用、加密参数及版本链，在同一事务中释放锁，然后提交。
6. 旧密文失去引用后进入清理流程。清理失败不回滚已经确认提交的新版本。

新文件的同名竞争由 `(parent_id, name)` 唯一约束拒绝；失败的一方不能覆盖已提交节点，也不能删除获胜方的密文。

### 8.2 失败与清理

| 失败位置 | 处理原则 |
| --- | --- |
| 新密文未写完 | 原数据库记录与旧密文继续有效，残留暂存对象等待清理 |
| 新密文已持久化但事务未提交 | 原版本继续有效，新密文仍是未提交对象 |
| 数据库已提交但旧密文未清理 | 新版本有效，旧密文可稍后清理 |
| 无法确定提交结果 | 重新读取数据库确认引用，不能直接删除可能已提交的新密文 |
| 数据库引用的密文缺失或损坏 | 报告数据异常，不能擅自回退到无引用文件 |

暂存对象及尚未提交的候选密文必须能关联产生它们的 `lock_id`。不能把 `owner_token`、密码或文件密钥暴露在文件名中。

清理器必须同时检查数据库引用与相关操作是否仍有效。禁止仅凭一次旧快照就删除当前仍可能被提交的文件；实际删除前要重新校验，避免与提交竞争。仍在活跃写入的暂存对象不能被清理。

### 8.3 目录与空间操作

- 改名或移动目录只修改该目录节点的名称或父关系，不批量重写后代完整路径。
- 防环检查、同名检查与修改放在同一个短写事务中。
- 递归删除目录前收集涉及的文件 ID 并申请文件写锁；提交前重新校验子树。如果子树已变化，释放并重试或返回冲突。
- 新写入在最终提交前检查父目录仍存在，不能把已删除目录下的候选文件提交成孤儿节点。
- 数据库先删除逻辑引用，随后清理失去引用的物理密文，读写排斥规则仍然适用。
- 移动整个容器时，由 service 协调本机应用库、容器库与文件系统。两份数据库和文件系统不具备天然的整体事务，失败后应根据已确认状态恢复，不能只改本机登记就报告成功。

## 9. 改密码与双密钥轮值

沿用两套文件数据密钥轮值的设计，不再增加第三套或为每个文件重复保存完整密钥材料。

### 9.1 普通改密

- 使用 SQLCipher 的改密能力修改容器数据库的密码保护。
- 文件数据密钥保持不变，独立密文文件不重写。
- 正确处理其他进程持有的旧数据库连接：需要时关闭、重开并重新验证密码；不能将解锁失败解释为持有进程已经退出。
- 改密失败或提交状态不确定时，验证数据库状态后再给出结果，不能直接报告成功。

### 9.2 完整改密

1. 持久化新的 `active` 文件密钥，并将旧文件密钥标为 `retiring`，形成可恢复状态。
2. 新写入使用活动密钥。提交时重新校验活动密钥，防止较早启动的写入重新提交旧密钥引用。
3. 逐文件获取写锁、生成新密文，再事务更新该文件的 `cipher_name`、`key_id`、`nonce` 与加密时间。
4. 已使用活动密钥的文件直接跳过。重新加密保持文件 ID、目录关系与内容版本链不变。
5. 所有文件不再引用旧密钥后完成数据库密码切换；验证成功后移除不再被引用的旧文件密钥并清理旧密文。
6. 任何中断都根据当前数据库内的密钥状态与实际文件引用继续执行，不能依据循环下标或只保存在内存中的进度判断完成。

双密钥状态要覆盖密码切换前、密码切换后但清理未完成等中断点。新密码不持久化；恢复时由用户提供必要密码。轮换、数据库改密及旧密钥移除的具体事务边界必须通过故障注入验证。

## 10. 打包、迁移和同步边界

- 打包必须获取数据库与所引用密文的一致快照，防止快照完成后对应密文被其他操作清理。
- 不能直接复制正在写入的单个 `veil.db` 作为完整备份，不能忽略尚未合并的数据库日志。
- 迁移副本或导出副本中不保留原设备的 `operation_locks`；清理的是导出副本的运行记录，不能擅自清空源容器中的活跃锁。
- 导入或迁移后先解锁验证容器身份及内容引用，再更新本机登记。重复 ID 或目标位置冲突时明确报错。
- `.veil` 打包格式、解包流程及所有依赖旧元数据格式的组件应同步适配新格式，不加入旧格式兼容分支。
- 用户设置同步与容器数据同步是后续两项独立能力。本次只确定稳定身份、字段归属与导出边界。
- `space_info.local_path`、`system_setting`、`local_record`、运行锁及本机查询端点不能直接作为跨设备业务配置同步。

## 11. 改造步骤与代码范围

| 顺序 | 工作 | 验收结果 |
| --- | --- | --- |
| 1 | 接入 SQLite/SQLCipher，统一目录、连接初始化、参数、版本升级与测试注入入口 | 本机库可以正常读写；容器库必须正确设置密码后才能读取；错误密码不生成明文替代库 |
| 2 | 落实应用库五张表及 service 存储接口 | 空间、登记、设置、本地记录均通过 service 访问 |
| 3 | 替换 JSONC 配置及桌面端最近记录 | CLI 不再依赖整体 `GlobalConfig`；桌面端不再使用 `localStorage["veil.recents"]` |
| 4 | 落实容器库三张表及父子树操作 | 文件列表、目录、版本链、密钥集合均由容器库管理，文件内容留在磁盘 |
| 5 | 用 SQLite 文件锁协议替换现有业务锁文件，并复用执行身份模块 | 同文件读读并发，读写与写写互斥；不同文件可以处理并行流式工作 |
| 6 | 接入写入提交、清理、改密与双密钥恢复 | 故障后以数据库状态恢复，旧凭证不能提交，不丢失已提交版本 |
| 7 | 适配打包解包、依赖容器格式的工具及客户端调用 | 独立迁移后可以打开；现有调用入口使用统一 service；受影响组件可构建且行为明确 |
| 8 | 完成回归、并发、故障与平台验证 | 满足下节验收场景；清楚记录尚未实机验证的平台 |

实现职责：

- core：保留底层文件流式加密、密钥材料处理、版本链比较、执行身份及系统检查；提供必要的存储底层能力。
- service：应用库访问、容器库业务访问、文件级锁、凭证校验、密钥轮换、恢复与客户端业务接口。
- CLI/桌面端/移动端：输入、展示、平台目录提供与统一执行入口适配，不自行编辑业务表或配置文件。
- 现有 `config.rs`、`spaces.rs`、`workflow.rs`、`veil_ops.rs`、链接与打包模块按实际依赖调整，不保留一个继续加载旧 JSONC 的旁路实现。
- 数据库驱动、SQLCipher 构建方式、日志模式和连接超时在底层集中管理，不能由不同客户端各自选择不兼容的格式或参数。

## 13. 当前实现状态与参考

已经接入普通 SQLite 应用库、固定 SQLCipher 4 容器库及上述八张表。service 管理空间、登记、类型化设置、本机记录、父子目录树、内容版本、文件租约、清理、普通改密、双密钥轮换和一致快照；CLI 与桌面端使用统一入口。旧 JSONC 配置、旧容器头部和第 1 版打包文件不再读取。

实现位于 `crates/veil-core/src/database.rs`、`crates/veil-service/src/storage/` 及对应业务模块。文件锁采用 30 秒租约、5 秒续租、30 秒默认等待和 20 毫秒退避；存活查询有整体预算，不能因多个无响应端点拖过等待期限。本机查询入口不可用时保留空端点，按 Unknown 和租约处理。

已验证普通改密不重写文件、完整改密最多两把文件密钥、不同改密中断点的恢复、旧数据库连接不能误写、旧凭证不能提交、同名新建竞争、读锁失效不发布明文、提交结果不确定时重读引用，缓存刷新不会覆盖移动恢复意图，以及争用同一链接时失败请求不会删除获胜入口或已提交容器。
