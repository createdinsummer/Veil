# Veil 全功能测试场景清单

本文只描述测试场景和预期结果，不提供操作命令。测试对象包括 `veil` CLI、交互式 shell、工作区容器、链接与全局配置、打包文件，以及项目附带的密码强度测试工具。

## 使用方式

- 每条场景都应至少覆盖一次正常路径和一个异常路径。
- 测试前应使用隔离的用户目录、工作目录和外置卷，避免污染真实数据。
- 同一场景需要在 Release 构建和 Debug 构建中分别确认时，应单独记录构建类型。
- “预期”描述的是用户可观察结果，不是内部函数调用结果；同时应检查退出状态、标准输出、标准错误、配置、链接、工作区和临时文件。
- 标记为“当前限制”的场景可能不会通过；它们用于暴露已知风险、兼容问题或未来应补强的行为。
- 
## 重要
- 先扫描代码的实现，之后，生成一个sh脚本，由用户执行，执行完成后，用户将脚本的所有输出，提供给你，你来查看和分析存在的bug
- 测试的时候密码使用"1"，涉及到动态不可控的变量，例如外置磁盘位置、交互式密码等可以在脚本执行的过程中由用户输入，这个脚本要等等用户输入，而不是一味的执行
- 自动完成生命周期的维护，以及测试数据的准备。

## 一、基础入口、帮助与输出

### 启动和帮助

- `GLB-01` 首次在新用户环境中启动：程序正常显示版本和安全模式，不因为缺少配置文件而失败。
- `GLB-02` 使用 Release 构建启动：版本信息说明当前为高安全强度，不显示 Debug KDF 警告。
- `GLB-03` 使用 Debug 构建启动：版本信息明确提示测试 KDF、调试构建和破解速度风险。
- `GLB-04` 使用开发、Alpha 或 Beta 版本号启动：除构建模式提示外，还应显示开发版本警告。
- `GLB-05` 不提供任何功能入口：显示错误和用法提示，退出状态应为参数错误。
- `GLB-06` 请求顶层帮助：列出初始化、文件管理、查看、打包、配置、链接和帮助等全部入口。
- `GLB-07` 请求每个子功能的帮助：名称、用法、参数、选项和默认值应与实际行为一致。
- `GLB-08` 请求文件类型帮助：清楚解释链接文件、元数据文件、密文文件和打包文件的用途。
- `GLB-09` 请求全部帮助：输出顶层帮助和全部子功能帮助，不应漏项或重复。
- `GLB-10` 请求不存在的帮助主题：返回明确的未知主题错误和稳定错误码。
- `GLB-11` 请求软件版本：版本号应与项目发布版本一致。
- `GLB-12` 在窄终端、宽终端和重定向输出中查看帮助：文字不应被截断、乱码或相互覆盖。
- `GLB-13` 在支持颜色的终端和关闭颜色的终端中运行：功能结果一致，颜色变化不影响可读性。
- `GLB-14` 将标准输出和标准错误分别重定向：正常信息进入标准输出，错误和用法提示进入标准错误。
- `GLB-15` 标准输出管道提前关闭，或平台仍暴露已关闭的标准输出描述符：程序应返回稳定 I/O 错误，不应 panic；macOS 可能由运行时把已关闭描述符替换为 `/dev/null`，此时以管道提前关闭场景验证。

### 参数解析

- `GLB-16` 缺少必需的容器参数：显示缺失容器错误，不得继续访问文件系统。
- `GLB-17` 缺少必需的源路径、容器内路径或导出路径：分别显示对应缺失参数错误。
- `GLB-18` 同一个值同时由位置参数和选项提供：按设计选择其中一种，或在冲突规则下明确拒绝。
- `GLB-19` 密码同时使用位置形式和选项形式：返回参数冲突错误。
- `GLB-20` 输入路径、输出路径或新旧密码同时使用两种写法：返回相应的参数冲突错误。
- `GLB-21` 提供未知选项：返回未知参数错误，不显示英文解析器原始提示。
- `GLB-22` 提供未知子功能：返回参数错误和用法提示。
- `GLB-23` 参数值包含空格、中文、符号、引号或前后空白：参数值应原样保留，不应被错误拆分。
- `GLB-24` 参数值以短横线开头：只要作为合法位置参数传入，就不应被误判为选项。
- `GLB-25` 重复提供同一个普通选项：行为应稳定，并明确是覆盖、报错还是接受最后一次值。
- `GLB-26` 错误发生后再次运行正常请求：前一次错误不应污染配置或后续行为。
- `GLB-27` 各种参数错误：退出状态和错误码应稳定，参数类错误与业务类错误不能混淆。

### 中文、英文和提示

- `GLB-28` 未设置语言变量：默认显示中文。
- `GLB-29` 设置为英文：帮助、提示、成功消息和错误消息一致切换为英文。
- `GLB-30` 设置为不支持的语言：应回退到默认语言，不应中断功能。
- `GLB-31` 提示级别为完整：首次创建、首次打包、首次解包和链接恢复提示均可出现。
- `GLB-32` 提示级别为简要：只保留链接恢复和解包相关关键信息。
- `GLB-33` 提示级别为关闭：提示不再出现，但核心结果和错误仍必须显示。
- `GLB-34` 配置中的提示级别与临时环境覆盖同时存在：临时覆盖优先，配置值保持不变。
- `GLB-35` 临时环境变量值非法：回退到已保存配置，不应导致启动失败。
- `GLB-36` 每个新容器首次创建：显示链接、工作区、打包和解包说明。
- `GLB-37` 首次打包和首次解包：分别显示链接、包文件、文件数量和新工作区的对应关系。
- `GLB-38` 链接被恢复或链接与同名打包文件并存：显示条件提示，即使一次性提示已经展示过。

## 二、密码输入与验证

- `PWD-01` 交互创建新密码：密码输入不回显，并要求再次确认。
- `PWD-02` 两次新密码不一致：拒绝继续，不创建容器、不写入配置。
- `PWD-03` 新密码为空：拒绝创建或修改，明确指出新密码不能为空。
- `PWD-04` 新密码只有空格、制表符或换行：应明确判定有效或无效，行为不能因终端平台而不同。
- `PWD-05` 新密码包含中文、Emoji、组合字符或非 ASCII 符号：加密、验证和重新打开均正常。
- `PWD-06` 新密码非常长：程序正确接受或给出明确上限，不应截断后静默使用。
- `PWD-07` 密码以空白开头或结尾：应保留原始密码，后续不能因自动去空格而无法打开。
- `PWD-08` 密码来源同时存在命令行、环境变量和终端输入：按命令行、环境变量、终端的优先级选择。
- `PWD-09` 环境变量未设置且没有终端：返回可理解的密码输入失败错误，不 panic。
- `PWD-10` 打开历史空密码容器：按兼容规则允许打开；新建或修改为空密码则必须拒绝。
- `PWD-11` 对需要密码的每个功能输入错误密码：功能失败，不展示元数据、不导出文件、不修改容器。
- `PWD-12` 在错误密码下执行添加：不得生成任何新密文文件。
- `PWD-13` 在错误密码下执行删除或移动：元数据和密文都应保持不变。
- `PWD-14` 在错误密码下执行导出：不得创建、截断或覆盖目标文件。
- `PWD-15` 在错误密码下执行打包：不得生成半成品包文件。
- `PWD-16` 标准输出、错误输出、日志和进程参数中：不应额外泄露密码内容。
- `PWD-17` 忘记密码后尝试各种恢复路径：项目不提供密码恢复，所有数据保持不可读取。

## 三、容器初始化与工作区布局

### 默认初始化

- `INIT-01` 使用普通容器名初始化：创建链接、工作区、元数据和全局配置记录。
- `INIT-02` 初始化空容器后查看内容：文件数量为零，并显示空状态。
- `INIT-03` 容器名包含中文、空格、点号、连字符或特殊符号：显示名称正确，默认链接名安全可用。
- `INIT-04` 容器名只有空白或清洗后为空：拒绝初始化，不产生残留文件和记录。
- `INIT-05` 默认链接名已经存在：使用时间或递增后缀生成新链接，不覆盖旧链接。
- `INIT-06` 同一秒内连续创建多个同名容器：每个容器拥有独立链接、ID 和工作区。
- `INIT-07` 两个容器使用相同展示名称：通过稳定 ID 区分，内容互不影响。
- `INIT-08` 指定自定义链接路径且父目录不存在：按设计创建父目录或明确拒绝，行为应稳定。
- `INIT-09` 指定已有链接路径：拒绝覆盖。
- `INIT-10` 指定扩展名不是链接格式的输出路径：拒绝初始化，且不留下工作区和配置记录。
- `INIT-11` 直接以链接文件名作为初始化目标：推导容器名称并创建对应链接。
- `INIT-12` 目标路径是目录或带有目录层级：容器展示名取最后一级名称。

### 默认、命名和专属工作区

- `INIT-13` 使用默认工作区：容器目录位于默认工作区根下，并使用稳定 ID 作为目录名。
- `INIT-14` 指定已注册的命名工作区：在对应根目录下创建容器目录。
- `INIT-15` 指定不存在的命名工作区：拒绝初始化并说明名称未注册。
- `INIT-16` 指定默认工作区名称：使用默认工作区配置。
- `INIT-17` 自定义命名工作区配置已存在但目录不可写：初始化失败并回滚。
- `INIT-18` 指定相对工作区路径：路径在初始化时固定为绝对路径，之后从其他目录使用链接仍能定位。
- `INIT-19` 指定目录作为专属工作区且目录为空：目录本身成为容器根，元数据直接位于其中。
- `INIT-20` 指定目录作为专属工作区且目录已有文件：拒绝初始化，原文件保持不变。
- `INIT-21` 专属工作区目录不存在：创建目录并初始化。
- `INIT-22` 专属工作区目录是普通文件：返回路径错误，不覆盖文件。
- `INIT-23` 同时指定命名工作区和显式工作区路径：返回冲突错误。
- `INIT-24` 指定专属模式但未提供工作区路径：返回缺少工作区路径错误。
- `INIT-25` 同时指定便携模式和任意工作区选项：返回冲突错误。
- `INIT-26` 显式启用便携模式：链接和工作区在链接所在卷内保持成对移动。
- `INIT-27` 链接位于识别出的外置卷或可移动卷且未指定工作区：自动采用便携布局。
- `INIT-28` 链接位于普通本地目录且未指定便携模式：使用默认工作区。
- `INIT-29` 工作区根、容器目录或链接创建到一半失败：清理新建目录、链接和配置记录。
- `INIT-30` 初始化过程中磁盘满、权限不足或文件系统只读：返回清晰失败信息，不留下孤立配置。
- `INIT-31` 初始化成功后的链接、元数据、密文和配置权限：按安全设计限制为当前用户可读写。

## 四、链接、配置与容器定位

- `RES-01` 使用容器显示名称定位：解析到正确工作区。
- `RES-02` 使用稳定容器 ID 定位：解析到正确工作区。
- `RES-04` 使用链接文件完整路径定位：解析到链接指向的工作区。
- `RES-05` 使用容器名称定位：只在配置中唯一匹配时成功，同名容器要求改用 ID 或链接。
- `RES-06` 普通命令输入直接指向容器的工作区目录：拒绝，并提示使用 `.veil-link`；`veil link` 可接受该目录用于恢复。
- `RES-07` 使用普通目录且其中没有元数据：拒绝，不把任意目录当容器。
- `RES-08` 使用打包文件直接访问：提示必须先解包，不把包当工作区。
- `RES-09` 显式输入 `.veil-link`：不根据同名 `.veil` 包猜测目标。
- `RES-10` 找不到容器或链接：返回找不到容器错误，不创建新容器。
- `RES-11` 多个容器展示名称相同：通过明确链接或 ID 仍可分别访问。
- `RES-12` 容器展示名称被修改但 ID 不变：原链接和配置记录仍应能定位容器。

### 链接恢复

- `RES-13` 链接被删除但配置保存了原始字节：下次访问时原样恢复链接并提示用户。
- `RES-14` 链接缓存可用但哈希不匹配：拒绝恢复，防止把损坏或篡改内容写回。
- `RES-15` 链接缓存十六进制内容损坏：返回缓存损坏错误，不 panic。
- `RES-16` 配置中没有链接原始字节缓存：拒绝自动恢复，不根据路径或名称猜测链接内容。
- `RES-17` 配置完全丢失但工作区和显式链接仍存在：通过链接路径访问；只有工作区时使用 `veil link` 重建入口。
- `RES-18` 缺失链接只与容器名一致：拒绝自动恢复，避免把名称误当成链接定位依据。
- `RES-19` 只操作一个容器：不得顺带恢复其他容器的缺失链接。
- `RES-20` 链接所在卷与记录卷不一致：报告目标卷不可用，不使用错误的相对路径。
- `RES-21` 通过名称、链接或稳定 ID 选择容器：最终都必须从 `.veil-meta` 得到同一个真实 `veil_id`，操作阶段再次校验身份。
- `RES-22` 链接、配置记录或工作区实际 `veil_id` 不一致：拒绝操作并报告 ID 冲突。
- `RES-26` 外置卷已挂载但盘符或挂载点变化：配置中的卷记录能够辅助重新定位。
- `RES-27` 外置卷未挂载：返回卷不可用错误，不创建空工作区。
- `RES-28` 链接内容格式损坏或缺少必需字段：明确报告链接格式错误。
- `RES-29` 链接工作区路径被编辑为绝对路径：拒绝越界重定向，不访问链接记录之外的路径。
- `RES-30` 链接包含缺失的稳定 ID：拒绝生成或使用，避免身份丢失。

## 五、添加文件与目录

### 文件和目录导入

- `ADD-01` 添加普通文本文件且不指定目标名：使用源文件名作为容器内路径。
- `ADD-02` 添加文件并指定新的普通名称：按指定名称保存。
- `ADD-03` 添加文件并指定多级目录路径：自动形成中间目录层级。
- `ADD-04` 添加时目标以目录分隔符结尾：保留源文件名并放入目标目录。
- `ADD-05` 添加空文件：成功保存，大小为零，导出后仍为空文件。
- `ADD-06` 添加二进制文件：内容逐字节一致，不受文本编码影响。
- `ADD-07` 添加大文件和接近容量上限的文件：成功或明确失败，不产生截断明文。
- `ADD-08` 添加文件名或目录名含中文、空格和混合符号的内容：列表、树形展示和导出均正确。
- `ADD-09` 添加深层嵌套目录：相对层级完整保留。
- `ADD-10` 添加目录且不指定目标前缀：使用源目录名作为容器内根路径。
- `ADD-11` 添加目录并指定目标前缀：所有子文件迁移到新前缀下。
- `ADD-12` 添加空目录：成功结束并提示没有可添加文件，不制造虚假目录条目。
- `ADD-13` 目录中包含符号链接：默认不跟随；应避免重复导入、循环和越界读取。
- `ADD-14` 目录中包含 FIFO、套接字或设备文件：应跳过或明确拒绝，不得阻塞。
- `ADD-15` 单个源本身是 FIFO、套接字或设备文件：拒绝为非普通文件。
- `ADD-16` 源路径不存在、已删除或在扫描期间消失：返回源不存在或读取失败。
- `ADD-17` 源文件或某个子目录无读取权限：返回明确错误，批量添加按事务规则回滚。
- `ADD-18` 目录遍历过程中遇到不可读取的子目录：报告路径和原因，不静默漏文件。
- `ADD-19` 源目录内容在扫描和读取之间发生变化：结果必须一致，不能出现元数据条目指向不完整密文。

### 目标路径和重复项

- `ADD-20` 添加文件到容器内目标 `./dir/file`：路径规范化后正常保存。
- `ADD-21` 添加时目标使用 `..`、绝对路径、根路径或空路径：拒绝路径逃逸和无目标路径。
- `ADD-22` 添加目标与已有文件完全同名：替换旧内容，列表不出现重复条目。
- `ADD-23` 添加目标与已有目录前缀相同：应明确处理“同名文件和目录并存”的兼容行为。
- `ADD-24` 同一批目录导入中出现重复目标：按最后一项覆盖，最终元数据只有一个条目。
- `ADD-25` 重复替换后检查旧密文：旧密文应从工作区清理；清理失败不应破坏新文件。
- `ADD-26` 使用错误密码添加：在任何密文写入前失败。
- `ADD-27` 批量加密中途失败：删除本批次新增密文，原元数据和原文件保持不变。
- `ADD-28` 元数据原子替换失败：清理新密文并保留旧元数据。
- `ADD-29` 输入路径或目标路径的参数冲突：返回参数错误。
- `ADD-30` 添加文件名在不同平台大小写规则下相同：必须避免静默覆盖或产生不可访问条目。

## 六、列表、树形、信息和存在性检查

### 列表

- `VIEW-01` 空容器列表：显示容器名、零文件数和空状态。
- `VIEW-02` 多文件列表：显示文件名、明文大小、加密时间和总大小。
- `VIEW-03` 文件顺序：按虚拟路径稳定排序，不受插入顺序影响。
- `VIEW-04` 大小边界：零字节、1 字节、1023 字节、1024 字节、MB 和 GB 边界显示合理。

## 九、修改密码

- `LINK-10` 缓存新链接失败：删除刚创建的链接，避免出现未登记入口。
- `LINK-11` 同一容器存在多个链接：任一链接的写入立即可被其他链接观察到。
- `LINK-12` 复制链接到另一目录：按卷身份和工作区相对路径判断是否仍可解析。
- `LINK-13` 复制链接到不同卷：必须验证目标卷，不应错误指向原卷或任意路径。
- `LINK-14` 链接文件被替换成普通文本、空文件或其他格式：明确报错。
- `LINK-15` 链接路径含中文、空格或深层父目录：创建、缓存和恢复均正确。

## 十五、元数据、密文和持久化数据

### 元数据

- `DATA-01` 元数据头部魔数、版本 3、算法、盐和 nonce：字段完整且可解析；旧版本明确拒绝。
- `DATA-02` 明文头部包含稳定 ID、展示名称和工作区类型：用于恢复的身份信息可读。
- `DATA-03` 加密区不包含明文文件路径、文件内容和密码：进行二进制检查确认。
- `DATA-04` 元数据被截断、魔数错误或头部长度越界：拒绝解析，不越界读取。
- `DATA-05` 元数据的加密区多一字节、少一字节或随机篡改：认证解密失败。
- `DATA-06` 元数据缺失：所有需要元数据的功能失败，不误报空容器。
- `DATA-07` 元数据算法标识未知：明确不支持，不能按错误算法解密。
- `DATA-08` 元数据 JSON 缺字段或类型错误：解密后反序列化失败，不部分加载。
- `DATA-09` 元数据中有重复虚拟路径：读取应稳定，危险操作应拒绝或采用明确规则。
- `DATA-10` 元数据指向的加密文件不存在：列表可显示条目，但导出失败并提示。

### 密文文件

- `DATA-11` 每个文件使用独立随机密文文件名：文件数量与元数据一致。
- `DATA-12` 每个文件使用独立 base nonce，并派生独立分块 nonce：同一明文重复添加时密文不同。
- `DATA-13` 单个密文被篡改：认证解密失败，不输出损坏明文。
- `DATA-14` 密文被替换为另一文件的密文或分块顺序被交换：nonce 或认证上下文不匹配时应失败。
- `DATA-15` 密文被截断：解密失败。
- `DATA-16` 密文文件缺失：删除操作可通过元数据完成；导出和改密应失败。
- `DATA-17` 工作区存在未被元数据引用的密文：不影响正常列表；需要记录孤儿文件治理策略。
- `DATA-18` 工作区权限发生变化：只读、无权读取和无权写入应有明确错误。
- `DATA-19` 添加和导出明显大于单个分块的文件：按固定大小分块处理，内存占用不随文件大小增长。
- `DATA-20` 完整改密明显大于单个分块的文件：旧密文到新密文采用单遍流式重写，峰值内存保持在数个分块以内。
- `DATA-21` 删除或截断任意分块：导出失败，不生成半截或未认证的输出文件。
- `DATA-22` 任意分块被篡改：对应分块认证失败，不得输出损坏明文。

### 链接和配置持久化

- `DATA-19` 链接文件版本、身份、卷、相对路径和算法字段完整。
- `DATA-20` 链接文件不保存密码、文件内容或绝对工作区路径。
- `DATA-21` 配置文件记录容器、卷、链接、缓存哈希和原始字节副本。
- `DATA-22` 配置中的稳定 ID、链接 ID 和元数据 ID一致。
- `DATA-23` 配置中的链接缓存哈希与文件实际内容一致。
- `DATA-24` 链接被删除但缓存仍在：可恢复为原字节。
- `DATA-25` 配置被删除但工作区和链接仍在：常规操作可继续或重建配置。

### 权限和秘密

- `DATA-26` 在 Unix 权限模型下检查配置、链接、元数据和密文：默认不对其他用户开放。
- `DATA-27` 密码不出现在命令行帮助、错误输出、配置和日志中。
- `DATA-28` 明文临时文件在使用后删除，创建时权限受限且不覆盖同名文件。
- `DATA-29` 程序崩溃后残留的临时文件：应能识别、清理且不被当作正式数据。
- `DATA-30` Debug 构建或测试 KDF 环境变量只改变性能参数，不改变格式兼容性。

## 十六、失败回滚与恢复

- `REC-01` 初始化失败：回滚工作区、链接和配置。
- `REC-02` 添加失败：回滚本批次新密文，旧文件仍可读取。
- `REC-03` 删除失败：原元数据和原密文仍一致。
- `REC-04` 移动失败：所有虚拟路径保持原样。
- `REC-05` 改密失败：旧密码仍可读，新密码不可读，临时文件清理。
- `REC-06` 打包失败：不留下可误认成功的包文件。
- `REC-07` 解包失败：清理新目录、链接和半成品。
- `REC-08` 配置保存失败：旧配置继续可用，内存中的改动不能部分写入。
- `REC-09` 链接缓存损坏且链接缺失：不能从不一致缓存恢复。
- `REC-10` 配置完全丢失但显式链接仍存在：通过链接路径访问；只有工作区时使用 `veil link` 重建入口。
- `REC-11` 链接和配置都丢失但工作区存在：可从元数据明文头部重建链接。
- `REC-12` 元数据损坏但密文仍在：没有恢复密码或完整性校验和时，不应伪造成功结果。
- `REC-13` 单个密文损坏：只影响该文件，元数据和其他文件仍可读取。
- `REC-14` 多个组件同时损坏：错误优先级清晰，不出现 panic、死循环或无界重试。
- `REC-15` 失败后重新运行同一正常操作：清理逻辑不应把合法文件误删。
- `REC-16` 添加文件过程中进程被杀死：旧元数据和旧密文保持可读；下次成功读取清理未提交密文。
- `REC-17` 删除文件过程中进程被杀死：内存中的删除不能破坏旧快照；元数据提交后旧密文最多成为可清理孤立文件。
- `REC-18` 修改密码过程中进程被杀死：旧密码或新密码中至少有一个能打开一套完整快照，不得出现新旧密钥混用的文件集合。
- `REC-19` 写元数据临时文件时断电或进程被杀：正式 `.veil-meta` 必须保持旧内容或完整新内容，不得出现半截 JSON/TLV。
- `REC-20` 单文件容器修改密码时进程被杀死：原文件必须保持旧 Header 或完整新 Header，不得在原位置留下部分覆盖。

## 十七、并发、一致性和性能

- `CON-01` 两个进程同时向同一容器添加不同文件：确认是否存在丢失更新；当前限制是无跨进程写锁。
- `CON-02` 一个进程添加、另一个进程删除：最终状态应可解释，密文不能出现错误引用。
- `CON-03` 一个进程移动、另一个进程读取：读取应得到操作前或操作后的完整元数据。
- `CON-04` 一个进程改密、另一个进程导出：导出只能使用旧状态或新状态，不能混用新旧密钥。
- `CON-05` 一个进程打包、另一个进程修改文件：包内容必须来自一致快照，否则明确失败。
- `CON-06` 两个进程同时修改全局配置：记录是否存在容器或链接丢失。
- `CON-07` 两个进程同时恢复同一缺失链接：最终链接字节正确，不互相覆盖。
- `CON-08` 两个链接同时操作同一工作区：写入必须能被另一链接观察到，同时注意并发覆盖。
- `CON-09` 不同容器并行增删：互不影响，不能相互修改元数据或密文。
- `CON-10` 大量小文件添加：文件数量、密文数量和元数据条目一致。
- `CON-11` 大文件添加、导出和打包：内存占用不随文件大小失控，进度和错误可见。
- `CON-12` 深目录树增删移动：不会因递归过深而崩溃。
- `CON-13` 长时间运行多个命令：文件句柄、临时文件和线程数保持稳定。
- `CON-14` 系统休眠、网络卷断开或外置盘拔出：操作失败后不破坏本地状态，重新挂载后可继续。
- `CON-15` 磁盘空间接近上限：添加、改密、打包和解包分别在安全点失败并回滚。

## 十八、端到端用户旅程

- `E2E-14` 多用户环境：不同用户目录、不同权限和共享外置卷的行为明确，不得互相读取数据。
- `E2E-15` 清理卸载：删除程序后确认容器数据仍在；按用户意图删除工作区和配置时不误删其他容器。

- `PLAT-02` Linux 默认工作区和 `/media`、`/mnt`、`/run/media` 外置挂载识别正常。
- `PLAT-03` Windows 不同盘符和外置盘识别正常。

## 二十、密码强度测试工具

- `BF-03` 使用工作区容器或链接：明确说明当前工具不支持该目标类型。
- `BF-04` 字典攻击命中密码：尽快停止其他任务并显示正确密码。
- `BF-05` 字典攻击未命中：完成全部候选并显示未找到。
- `BF-06` 字典文件不存在、不可读、为空或只有空白行：给出明确结果。

- `BF-17` 历史文件不存在、为空、损坏或包含重复密码：攻击可继续，重复项被过滤。

## 二十一、三个核心配置文件内容检查

本节中的“三个核心配置文件”固定指：

1. 全局配置 `~/.veil/config.toml`。
2. 容器入口文件 `<名称>.veil-link`。
3. 工作区元数据文件 `<工作区>/.veil-meta`。

检查时既要读取文件内容，也要记录文件大小、权限、哈希和字段变化，不能只确认“文件存在”。

- `CONF-01` 初始化成功后检查全局配置：文件存在，当前用户可读写，其他用户不应具备写权限；配置版本、默认工作区、容器、卷和链接记录均可解析。
- `CONF-02` 检查配置中的容器记录：`veil_id`、展示名称、工作区名称或路径、目录名、创建时间、链接列表均正确，且记录数量与工作区实际容器数量一致。
- `CONF-03` 检查配置中的卷记录：卷 ID、标签、挂载路径、是否外置和最近发现时间存在；普通本地目录与外置卷的记录应可区分。
- `CONF-04` 检查配置中的链接记录：路径、稳定 ID、展示名称、目标卷、相对路径、状态、内容哈希和 `raw_hex` 均存在。
- `CONF-05` 将配置里的链接 `raw_hex` 解码后与实际 `.veil-link` 逐字节比较：必须完全一致。
- `CONF-06` 若系统提供 BLAKE3 工具，重新计算链接的 BLAKE3 哈希并与配置中的 `content_hash` 比较；工具缺失时明确跳过，不误报通过。
- `CONF-07` 检查 `.veil-link`：版本、创建时间、稳定 ID、展示名称、相对工作区路径、卷 ID、卷标签和算法字段完整，引用关系与全局配置一致。
- `CONF-08` 检查 `.veil-link` 敏感信息：不得包含密码、文件明文内容或宿主机绝对工作区路径。
- `CONF-09` 检查 `.veil-meta` 明文头：魔数、头部长度、版本、盐、算法、nonce、稳定 ID、展示名称和工作区类型完整，稳定 ID 必须与配置和链接一致。
- `CONF-10` 检查 `.veil-meta` 加密区：不得直接出现原始文件路径、文件名、文件明文和密码；头部长度不得越界或指向错误位置。
- `CONF-11` 连续添加多个文件后比较三个文件：稳定 ID 和容器身份不得变化；链接除必要的观测状态外不得失配；元数据文件必须能重新解析出全部文件。
- `CONF-12` 修改密码前后检查三个文件：配置和链接身份保持不变；元数据盐、nonce、密文和哈希应变化；旧密码不能使用新元数据，新密码可以完整读取。
- `CONF-13` 删除链接并从配置恢复后再次检查三个文件：恢复后的链接字节、配置缓存和元数据稳定 ID 仍然一致。
- `CONF-14` 删除配置后从链接或工作区重建记录：新配置中的容器、卷、链接记录必须与现有链接和元数据一致，不能生成冲突身份。
- `CONF-15` 配置或注册流程出现重复 `veil_id`：加载、保存或创建必须返回冲突错误，不得静默覆盖原容器记录。

## 二十二、程序运行产物与增量文件检查

运行产物包括 `.enc` 密文、`.veil` 包文件和操作期间产生的临时文件。每次文件操作都应记录操作前后的文件数量、文件总大小、元数据大小、关键哈希和导出内容。

- `ART-01` 添加一个非空文件：活动 `.enc` 数量增加一，新增密文大小应等于对应明文大小加认证标签长度，元数据条目数量同步增加一。
- `ART-02` 添加一个空文件：产生独立密文，导出后仍为零字节，元数据记录的大小必须为零。
- `ART-03` 对同一明文使用不同目标重复添加两次：两次生成的随机密文文件名和密文内容不同，活动条目各自自洽。
- `ART-04` 在 `.enc`、`.veil-meta` 和 `.veil` 中搜索唯一的明文标记：不得出现目标文件的明文内容。
- `ART-05` 添加目录并包含 N 个普通文件：活动 `.enc` 数量增加 N，元数据条目增加 N，物理文件总大小按 N 个密文累加。
- `ART-06` 连续执行单文件添加、目录添加、导出和删除：输出状态、密文数量、元数据条目数量和实际容器占用应逐步一致。
- `ART-07` 用相同目标覆盖旧文件：活动 `.enc` 数量不得继续增长，新明文可导出，旧密文不得继续被元数据引用。
- `ART-08` 删除文件或目录：活动 `.enc` 和元数据条目同步减少，容器物理占用随之下降；不可达旧密文不应影响列表。
- `ART-09` 添加失败或错误密码：工作区中的正式 `.enc` 数量、元数据字节、全局配置字节和链接字节保持不变。
- `ART-10` 正常操作结束后检查临时文件：工作区、配置目录和打包目标目录不得残留 `.tmp`、`.bak`、半包或密码修改暂存文件。
- `ART-11` 打包后检查 `.veil`：魔数、版本、头部长度、元数据长度和文件数量与容器一致。
- `ART-12` 比较 `.veil` 中的元数据区与工作区 `.veil-meta`：两者逐字节一致，打包不得重复加密或重新序列化元数据。
- `ART-13` 比较 `.veil` 中每个文件条目的密文与工作区对应 `.enc`：逐字节一致；条目名称和顺序与元数据清单一致。
- `ART-14` 打包空容器：包内元数据有效、文件数量为零、没有多余文件条目。
- `ART-15` 从包中解包后再次执行产物检查：新工作区的 `.enc` 数量和名称不必与原工作区完全相同，但内容、大小和元数据引用必须一致。
- `ART-16` 检查 `info` 的“实际容器占用”：应与目录中所有实际文件的字节总数一致，而不是只统计元数据。

## 二十三、外接磁盘反复断开与重连

本节要求人工执行真实卸载和重新挂载，脚本只能暂停等待用户操作，不能强制推出磁盘。测试使用一个位于本地卷、指向外置工作区的链接副本，避免在 `/Volumes` 下创建影子目录。

- `EXTC-01` 外置卷初始化后：链接和工作区均位于外置卷，同时创建一个本地卷链接副本，两个链接指向同一稳定 ID。
- `EXTC-02` 卸载前的基线检查：记录 `.veil-meta` 哈希、`.enc` 数量和哈希、链接身份、配置文件哈希和导出内容。
- `EXTC-03` 第 1 次断开：外置卷不可访问时，通过本地链接副本访问应返回卷不可用或容器不可达错误；不得创建空工作区或 `/Volumes` 下的影子目录。
- `EXTC-04` 第 1 次重连：重新挂载后，通过本地链接副本列表、导出和展开树形均成功，导出内容逐字节一致。
- `EXTC-05` 重连后继续添加文件：活动 `.enc` 数量和元数据条目按新增数量增加，配置和链接身份不变。
- `EXTC-06` 连续执行至少 3 次“卸载、不可用验证、重新挂载、读取和写入”循环：每次恢复后容器均可继续使用。
- `EXTC-07` 每个周期结束后比较三个核心配置文件：稳定 ID 不变，元数据可解析，配置记录仍指向实际存在的卷和链接。
- `EXTC-08` 外置卷不可用期间：操作失败后本地工作区、配置和本地链接副本不得被删除或改写为错误状态。
- `EXTC-09` 外置卷仍在挂载时用户无法卸载：脚本应明确跳过不可用测试并记录原因，不得把“卷仍挂载”误报为产品失败。
- `EXTC-10` 重连后挂载点与配置记录不同：按照项目设计，应报告卷不可用或通过明确机制重新定位，不能静默指向错误路径。
- `EXTC-11` 在读写过程中拔出外置盘：命令应返回错误，内存或本地状态不得留下半提交引用；重新挂载后旧数据仍可读取。
- `EXTC-12` 测试结束并重新挂载后：临时目录可清理，外置卷不再被终端工作目录、脚本子进程或文件句柄占用。

## 二十四、建议的最小回归组合

如果只能执行一组精简回归，应至少覆盖以下用户旅程：

1. 新建默认容器、专属容器、便携容器和外置卷容器。
2. 添加普通文件、空文件、二进制文件、中文空格路径、目录树和重复目标。
3. 查看列表、树形、信息和文件、目录、根目录、缺失路径的存在性。
4. 导出并逐字节比对，检查覆盖、缺失密文和损坏密文。
5. 删除文件、递归删除目录、移动文件、移动目录和各类冲突。
6. 修改密码并确认旧密码失效、新密码成功、失败时回滚。
7. 打包、解包、错误密码、损坏包、重复解包和路径逃逸防御。
8. 删除链接后的缓存恢复、配置丢失后的重建、卷不可用错误。
9. 配置提示级别、语言切换、帮助、参数冲突和错误码。
10. Shell 全命令流程、EOF、未知命令和带空格路径。
11. 并发添加、并发改密、并发打包和配置并发保存。
12. 元数据、链接、配置和密文的篡改、截断、缺失与权限异常。
13. 三个核心配置文件的内容、哈希、权限和身份一致性。
14. 文件增删前后的 `.enc` 数量、元数据条目、物理占用和包内容一致性。
15. 外置卷至少三次断开与重连，并在每次重连后执行读取、导出和继续写入。
